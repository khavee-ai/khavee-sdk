<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app-supplied tool `execute(args)` → ToolExecutor | A developer-registered function body runs inside the host; `args` are not schema-validated at runtime (explicit out-of-scope per REQUIREMENTS no-Zod constraint) |

This is a types-and-dispatcher phase: no network, no auth, no persistence, no untrusted external input beyond the existing tool-execution path.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Denial of Service | `ToolExecutor.execute()` invoking app-supplied `fn(args)` | mitigate | Preserve the existing try/catch unchanged: every fn call is wrapped, a throw returns `{success:false, message}` instead of propagating and crashing the host (verified by Task 3 test) |
| T-01-02 | Tampering | `args` passed to a tool's `execute` (no runtime schema validation) | accept | Explicitly accepted per REQUIREMENTS out-of-scope (no Zod/schema library, beginner-DX constraint); `Tool.parameters` is descriptive type-level shape only, validation is the tool author's responsibility |
| T-01-SC | Tampering | pnpm install of vitest/@vitest/coverage-v8 | mitigate | Both packages are already present and in active use in this same monorepo (packages/providers/openai-stt-tts); adding an existing in-repo devDependency to one more workspace package is not a new supply-chain surface (RESEARCH Package Legitimacy Audit) — no [ASSUMED]/[SUS] packages introduced |
</threat_model>
