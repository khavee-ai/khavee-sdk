## Objective

Implement the JaiTTS adapter as demo-local code and integrate it into the demo page so the full speech pipeline works end-to-end: speech → VAD → Thonburian STT → LLM → JaiTTS TTS → audio playback. Covers requirement ADPT-02.

## Context

From `04-CONTEXT.md` and `04-RESEARCH.md`:
- `jai-tts` service runs at `http://localhost:8002`, expects `POST /synthesize` with JSON `{"text": string}`, returns raw `audio/wav` bytes (24kHz/mono/16-bit per CONTEXT.md Specific Ideas)
- `TTSProvider.speak()` contract: returns `Promise<void>`, accepts caller-supplied `AudioContext` to decode/play through
- `TTSPlayer.speak()` in `packages/providers/openai-stt-tts/src/TTSPlayer.ts` has the exact decode/playback pattern to replicate: `audioContext.decodeAudioData()` → `AudioBufferSourceNode` → dual-path (analyser + destination)
- `AudioContext.decodeAudioData()` auto-resamples, so jai-tts's 24kHz output plays correctly regardless of the AudioContext's sample rate (CONTEXT.md Code Context)

## Tasks

### Task 1: Implement JaiTTS adapter in demo app

**File:** `src/app/generic-demo/adapters/JaiTTSAdapter.ts` (new)
**Dependencies:** None

Create the TTS adapter class that:
- Implements `TTSProvider` interface from `@khaveeai/core`
- Constructor accepts `{ baseUrl?: string }` config, defaults to `http://localhost:8002`
- Has capability flag `supportsStreaming = false`
- `speak(text: string, audioContext: AudioContext, opts?: { voice?: string; speed?: number; signal?: AbortSignal }): Promise<void>` method:
  - POSTs `fetch(`${baseUrl}/synthesize`, { method: 'POST', headers: {'Content-Type': 'application/json'}, body: JSON.stringify({ text }) })` with timeout via `AbortSignal.any([AbortSignal.timeout(60000), opts?.signal].filter(Boolean))`
  - Gets raw `audio/wav` bytes as `response.blob()` then `blob.arrayBuffer()`
  - Decodes via `audioContext.decodeAudioData(arrayBuffer)` to get `AudioBuffer`
  - Creates `AudioBufferSourceNode`, connects it to dual paths: an `AnalyserNode` (for lip-sync) and `audioContext.destination`
  - Starts playback via `source.start()`
  - Normalizes errors via `error instanceof Error ? error : new Error(String(error))`
- Silently ignores `opts?.voice` and `opts?.speed` (jai-tts hardcodes voice/speed per CONTEXT.md D-04)

**Verification:**
- TypeScript compiles without errors
- If jai-tts service is running, a real text POST produces decodable WAV audio
