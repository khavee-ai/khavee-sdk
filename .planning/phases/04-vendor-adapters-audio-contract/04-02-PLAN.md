<objective>
Build `JaiTTSProvider` — a thin HTTP adapter implementing `@khaveeai/core`'s `TTSProvider` interface by POSTing Thai text to the local `jai-tts` FastAPI service (port 8002), receiving raw `audio/wav` bytes, and decoding/playing them through the caller-supplied Web Audio `AudioContext` (the same dual-path decode/playback pattern `TTSPlayer` uses). Covers requirement ADPT-02.

Purpose: Lets the generic pipeline use JaiTTS voice-cloning for TTS — proving the Phase 1 `TTSProvider` abstraction holds against a real non-OpenAI vendor.

</objective>

From packages/core/src/types/pipeline.ts:
```typescript
export interface TTSProvider extends Provider {
  readonly supportsStreaming: boolean;
  speak(
    text: string,
    opts: {
      audioContext: AudioContext;
      onAudioData?: (analyser: AnalyserNode, audioContext: AudioContext) => void;
      voice?: string;   // D-04: silently ignored — jai-tts hardcodes its default voice
      speed?: number;   // D-04: silently ignored — jai-tts hardcodes speed=1.0
      signal?: AbortSignal;
    }
  ): Promise<void>;
}
```

`Provider` (from packages/core/src/types/providers.ts) requires a `name` string.

The backend contract (from /Users/whitemalt/Documents/jai-tts/main.py):
- `POST /synthesize` accepts JSON `{"text": string}` (Pydantic `SynthesizeRequest`)
- Returns `200` with raw `audio/wav` bytes (`Response(content=wav_bytes, media_type="audio/wav")`)
- TTS-direction wire format: 24kHz, mono, 16-bit PCM (soundfile defaults — 04-CONTEXT.md Specific Ideas)
- voice/speed are hardcoded server-side; no auth

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SDK adapter → jai-tts HTTP | Adapter sends text over localhost HTTP to an unauthenticated local FastAPI service and decodes the returned WAV bytes client-side. Per D-01 there is no auth — local-only demo service, not exposed to a network/customer trust edge. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Denial of Service | jai-tts /synthesize (hung/slow F5-TTS, possibly on CPU fallback) | mitigate | `AbortSignal.any([AbortSignal.timeout(this.timeoutMs), opts.signal])` default 60s (D-03) bounds a hung backend; timeout abort normalizes through `error instanceof Error ? ...`. |
| T-04-06 | Tampering | Malformed/non-WAV bytes returned causing decode failure | mitigate | `decodeAudioData` rejection is caught by the try/catch and surfaced as a normalized Error, not a crash; non-2xx is rejected before decode with the status + body. |
| T-04-07 | Tampering | SSRF via developer-overridden `baseUrl` | accept | `baseUrl` is developer-supplied constructor config (same trust assumption as OpenAI adapters' `endpoint`), not end-user input — out of scope for this phase's threat model (RESEARCH Security Domain). |
| T-04-08 | Information Disclosure | Detached ArrayBuffer / double-read after decode | mitigate | `arrayBuffer.slice(0)` passed to decodeAudioData (Pitfall 4) avoids detaching the buffer used elsewhere. |

No npm/pip/cargo installs in this plan (zero new dependencies — all APIs are native Node/browser globals per RESEARCH). No package-legitimacy checkpoint required.
