## Context

## Tasks

### Task 1: Document audio wire format

**File:** `src/app/generic-demo/AUDIO_FORMAT.md` (new, or add to existing demo README)
**Dependencies:** 04-01 and 04-02 complete (both adapters working)

Create documentation that specifies:
- **STT direction (VAD → Thonburian):**
  - Input to `ThonburianSTTAdapter.transcribe()`: WAV blob from MicVAD's `encodeWAV()`
  - Format: 16000 Hz sample rate, mono channel, 32-bit IEEE float PCM (WAV format code 3)
  - Sent via `multipart/form-data` with field name `file` to thonburian-stt's `/transcribe` endpoint
  - Response: JSON `{"text": "<Thai transcript>"}`
- **TTS direction (JaiTTS → Demo):**
  - Input to `JaiTTSAdapter.speak()`: Thai text string
  - JaiTTS response: raw `audio/wav` bytes at 24000 Hz sample rate, mono channel, 16-bit PCM
  - Decoded via `AudioContext.decodeAudioData()` which auto-resamples to the AudioContext's sample rate
  - Played back via `AudioBufferSourceNode` connected to `audioContext.destination`
- Note that formats are direction-specific and not symmetric (16kHz float32 vs 24kHz int16)

**Verification:**
- Documentation clearly specifies both directions with exact sample rates, encoding, and channels
- Someone could reproduce the wire format from this doc alone without reading adapter source code

### Task 2: Create round-trip test script

**File:** `src/app/generic-demo/__tests__/roundtrip-audio-contract.test.ts` (new, or use vitest's `test.only` / `test.skip` to make it opt-in)
**Dependencies:** Task 1 (format docs exist)

Create an opt-in test that:
- Requires both thonburian-stt and jai-tts services to be running (fails fast with clear error if not)
- **STT leg:** Generates or loads a sample Thai-speech WAV file (16kHz/mono/float32), posts it to thonburian-stt, asserts response contains `{text}` field and that text is non-empty
- **TTS leg:** Posts a known Thai text string to jai-tts, asserts response is decodable as WAV (via `audioContext.decodeAudioData()` or Node's `wav` decoder), asserts sample rate is 24000 Hz
- **Round-trip:** (Optional) Records a live utterance, transcribes it, synthesizes that text, and asserts the synthesized audio is valid WAV (not checking content equality, just format)
- Is NOT part of the default `pnpm test` suite — document how to run it explicitly (e.g., `vitest run src/app/generic-demo/__tests__/roundtrip-audio-contract.test.ts`)

**Verification:**
- When both services are running, test passes
- When either service is down, test fails with clear error message
- Test does not run in CI or as part of `pnpm test` without explicit invocation
