<objective>
Wire the two strategy seams (plans 01/02) into a public, abuse-resistant REST route that mints OpenAI ephemeral tokens for anonymous visitors. This plan delivers all four REST requirements: anonymous access (REST-01), key-never-leaves-server (REST-02), per-IP + sitewide-daily rate limiting (REST-03), and `Cache-Control: no-store` (REST-04). A standalone harness proves the rate-limit math, trust-model override, and response shaping without a live WP install.

Purpose: This is the integration-risk core of the milestone — the wire contract `OpenAIRealtimeProvider.connect()` consumes byte-for-byte, plus the abuse mitigations that protect the site owner's OpenAI billing from the first commit (retrofitting is a breaking change per PITFALLS.md).

Output: `RateLimiter.php`, `SessionController.php`, `Plugin.php`, the final hook-registration wiring in `khaveeai.php`, and `tests/rest-logic-harness.php`.

From plan 01 — ConfigSourceInterface (Khavee\Plugin\ConfigSource):
- get_runtime_config(): array — keys instructions, voice, avatar_url, model
- get_api_key(): string

From plan 02 — TokenProviderInterface (Khavee\Plugin\TokenProvider):

- failure surfaced via the mechanism plan 02 chose — read OpenAiDirectTokenProvider.php to confirm whether it throws TokenMintException or returns ['error'=>'mint_failed']

WIRE CONTRACT — OpenAIRealtimeProvider.connect() (OpenAIRealtimeProvider.ts:195-219, PATTERNS.md SessionController section):
- Request: POST with JSON body { "sessionConfig": { ... } }
- Client checks token paths in this order: tokenData.data?.ephemeralToken -> data?.value -> ephemeralToken -> value. data.ephemeralToken is checked FIRST -> that is the canonical field to populate.
- Success response MUST be at minimum: { "data": { "ephemeralToken": "ek_...", "sessionId": "..." } }
- sessionId read from tokenData.data?.sessionId.
- realtime.ts:50-55 confirms the same { data: { ephemeralToken, sessionId } } shape.

Route naming (Claude's discretion per CONTEXT.md): namespace khaveeai/v1, route /session, method POST only. permission_callback => '__return_true' (PITFALLS.md Pitfall 2 / STACK.md nonces row — NOT wp_verify_nonce/is_user_logged_in).

Rate-limit thresholds (CONTEXT.md D-01..D-04):
- D-01: per-IP 5 mints per 10-minute window
- D-02 + D-03: sitewide daily cap 200 mints/day, tracked independently of the per-IP counter (BOTH checked)
- D-04: thresholds hardcoded PHP defaults, each overridable via a wp_filter — NOT settings-page fields

Transient shapes (PATTERNS.md RateLimiter section):
- Per-IP: transient key "khaveeai_rl_{ip}", TTL 10*MINUTE_IN_SECONDS
- Sitewide daily: transient key "khaveeai_daily_mints", TTL DAY_IN_SECONDS

Status-code contract:
- 200 success { data: { ephemeralToken, sessionId } }
- 429 rate-limited/cap-exceeded, generic JSON body, no detail (D-05)
- 502 OpenAI mint failure, generic body, no leaked OpenAI detail (D-09)
- 503 missing/empty API key { error: 'khaveeai_not_configured' } (ARCHITECTURE.md Pattern 3)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Anonymous browser/script -> WP REST route | Untrusted, unauthenticated input crosses here; route is public by design |
| WP REST route -> ConfigSource/TokenProvider | Server-side; API key resolved and used here, never returned outward |
| Client sessionConfig fields -> mint_session | instructions/voice are untrusted and overridden; other fields pass through |
| REST response -> browser / HTTP caches | API key and OpenAI error detail must never cross; Cache-Control: no-store prevents shared-token caching |
