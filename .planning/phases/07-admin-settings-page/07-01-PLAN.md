<objective>
Extend Phase 6's config-source seam so the settings page (07-02) and Phase 8's frontend embed can ask one question — "is the avatar configured?" — through a single `is_configured(): bool` method, and migrate avatar storage from a pre-resolved URL string to a Media Library attachment ID resolved at read time (per ARCHITECTURE.md and RESEARCH.md Pattern 3 / Open Question 1).

Purpose: This is the contract layer the rest of Phase 7 builds against. Resolving the avatar-storage design and adding `is_configured()` here (Wave 1) means 07-02 and 07-03 implement against a fixed interface, and Phase 8 inherits a ready `is_configured()` check without re-deriving it from `get_api_key()`.

Output: Modified `ConfigSourceInterface` (one additive method), modified `WpOptionsConfigSource` (implements the method + resolves `avatar_url` from a stored `avatar_attachment_id`), and a new bare-PHP test harness covering both the `is_configured()` logic and the attachment-ID-to-URL resolution defaulting.
</objective>

<decision_coverage>
CONTEXT.md decisions implemented by this plan (D-13: exposes the empty-key check as the additive `is_configured()` helper on `ConfigSourceInterface` rather than letting downstream re-derive it; D-12: `is_configured()` is the empty-key gate the settings banner and Phase-8 embed notice key off — a wrong key is NOT guessed here, only emptiness; D-14: this plan adds the `is_configured()` contract that 07-02's settings-page "not configured" banner calls). This plan does not touch settings-page UI, avatar upload, or any other decision.
</decision_coverage>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| wp_options (DB) → PHP read | Stored settings blob (incl. attachment ID) read into the config source; trusted store but values must be type-coerced |
| ConfigSourceInterface → Phase 6 SessionController / Phase 8 embed | Downstream consumers depend on the stable return shape and on `is_configured()` never leaking the key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07A-01 | Information Disclosure | is_configured() / get_runtime_config() | mitigate | `is_configured()` returns only a bool derived from key presence — never returns or logs the key itself; `get_runtime_config()` already excludes `api_key` from its array (Phase 6 contract preserved) |
| T-07A-02 | Tampering | avatar_attachment_id read | mitigate | `(int)` cast + `$id > 0` guard + `wp_get_attachment_url()` false-coercion prevent a malformed stored ID from producing a non-string or `false` avatar_url that downstream code mis-handles |
| T-07A-03 | Tampering | non-array wp_options value | accept | Existing `is_array()` guard already normalizes a corrupted option to `[]`; no new attacker path introduced by this plan |
| T-07A-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan — WordPress-core functions and PHP built-ins only; nothing to audit |
</threat_model>
