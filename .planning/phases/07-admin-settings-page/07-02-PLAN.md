<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser (admin form POST) → options.php → sanitize_callback | Untrusted input crosses here even though the page is manage_options-gated — a compromised admin session or CSRF (if nonce failed) could submit arbitrary field values |
| options.php → wp_options['khaveeai_settings'] | Sanitized array is persisted; Phase 6's read path (and Phase 8) trust this to be well-formed |
| ConfigSourceInterface → render_page output | The stored key must NEVER round-trip into any HTML attribute unmasked; is_configured() must never leak the key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07B-01 | Elevation of Privilege | render_page() via direct URL navigation | mitigate | FIRST statement of render_page() is `if ( ! current_user_can( 'manage_options' ) ) wp_die(...)` — independent of add_menu_page()'s capability arg per Pitfall 3 / SET-05 |
| T-07B-02 | Cross-Site Request Forgery | settings form POST to options.php | mitigate | Use register_setting() + settings_fields(OPTION_GROUP) — WP core's options.php handler verifies the `update_plugins_nonce_...`/`_wpnonce` automatically; never hand-roll the POST handler or skip settings_fields() in the form (RESEARCH.md "Don't Hand-Roll" row) |
| T-07B-03 | Information Disclosure | API key echoed into HTML source | mitigate | The key field's value attribute is ALWAYS mask_api_key()'s output (sk-••••••<last4>); never `value="<?php echo $raw_key ?>"`. acceptance_criteria grep enforces no raw-key-in-attribute. Masking is server-side at render time per Architectural Responsibility Map. |
| T-07B-04 | Tampering (self-inflicted data loss) | masked-placeholder overwrites stored key on unrelated saves | mitigate | sanitize_api_key compares submitted vs mask_api_key(existing); equal → return existing (D-05, Pattern 2). Harness case proves placeholder-preservation. |
| T-07B-05 | Tampering | empty field interpreted as "delete key" | mitigate | D-06: deletion only via the separate remove_key checkbox control; an emptied field that isn't the mask-of-empty returns existing unchanged. Harness case proves empty-is-not-delete. |
| T-07B-06 | Spoofing / Tampering | malformed API key format submitted | mitigate | D-08: light format check rejects empty-after-trim or non-sk- prefix via add_settings_error('khaveeai_settings','khaveeai_api_key_invalid_format',...); returns existing on rejection (no overwrite with bad value) |
| T-07B-07 | Stored XSS | instructions textarea rendered back to the page | mitigate | sanitize_textarea_field() on save; esc_textarea() on output; same discipline for the voice field via sanitize_text_field + esc_attr. Never echo any settings field unescaped. |
| T-07B-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan — WordPress-core functions and PHP built-ins only |
