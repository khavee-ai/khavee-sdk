<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host page → bundle | The bundle reads server-rendered `data-khaveeai-config` JSON; this JSON is produced by trusted PHP (plan 02), but the bundle must not assume it; malformed JSON must fail gracefully, not throw uncaught |
| bundle → REST route | The bundle POSTs to the proxy endpoint to mint a token; it never holds an API key (backend-proxy assumption) |
| bundle → host global scope | The IIFE must not leak React/ReactDOM globals into any theme/plugin's window |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | global scope (window.React leak) | mitigate | esbuild `--format=iife` with no `globalName`; `bundle-isolation-check.mjs` smoke test asserts no leak, run in build pipeline (D-10) |
| T-08-02 | Elevation of Privilege | mic/token activity on load | mitigate | No `connect()` call outside an explicit click handler; mic prompt + token mint fire only on first user gesture (D-01, EMBED-05) |
| T-08-03 | Information Disclosure | embedded API key | mitigate | Bundle constructs provider with `useProxy: true` only, never `apiKey`; grep gate in acceptance criteria asserts no `apiKey` reference |
| T-08-04 | Denial of Service | malformed config JSON crashing the mount loop | accept | Single mount-point failure is isolated per-element; the page does not depend on the widget; low impact |
| T-08-SC | Tampering | npm installs (esbuild, react, react-dom) | mitigate | RESEARCH.md Package Legitimacy Audit approved esbuild/vite (slopcheck [OK]); react/react-dom already in workspace devDependencies — no new [ASSUMED]/[SUS] package introduced |
</threat_model>
