<objective>
Extend Phase 6's `SessionController::apply_trust_model()` so EMBED-02's per-instance voice/instructions overrides — which arrive INSIDE the `sessionConfig` the bundle already sends on every request (`sessionConfig.audio.output.voice` and `sessionConfig.instructions`, populated by `OpenAIRealtimeProvider` from its `RealtimeConfig.voice`/`.instructions`) — actually take effect at the session level, while keeping the Phase 6 D-07 jailbreak gap closed. A candidate `voice` is honored only when it is one of the 10 known OpenAI voices; a candidate `instructions` is honored only within a length cap; anything else silently falls back to the admin's global config. No new wire field is introduced and no client-sent field is blindly trusted. No changes to `ConfigSourceInterface`/`TokenProviderInterface` signatures.

Purpose: This is the security-critical half of EMBED-02. Phase 7's history (CR-01/CR-01-NEW: the exact "unvalidated voice value reaches the vendor" bug class, caught twice) makes this the highest-priority validation surface in the phase. The override values flow through the SAME `sessionConfig` fields Phase 6 already forces — this plan changes WHICH value is forced (validated-instance-value-or-global), never whether forcing happens.
Output: a modified `SessionController.php` and extended `rest-logic-harness.php` cases.

Note on avatar (D-05's third field): the avatar override is NOT validated here. Avatar never reaches OpenAI / `sessionConfig` — it is purely client-side chrome resolved PHP-side in plan 08-02's `AvatarRenderer` (attachment-ID → `avatarUrl` in the mount-point JSON, already validated there). Validating avatar in `SessionController` would be dead code (no producer puts an avatar into `sessionConfig`). EMBED-02's avatar override-or-fallback is covered by plan 08-02's `render-logic-harness.php`, not here.

| Boundary | Description |
|----------|-------------|
| anonymous client → REST route | The bundle (any visitor) POSTs `{ sessionConfig }` whose voice/instructions are attacker-controllable; this is untrusted input crossing into the token-mint flow that ultimately reaches OpenAI |
| validated config → OpenAI | Only allowlist/cap-validated voice/instructions may reach mint_session(); everything else is forced to the admin global |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-08-09 | Tampering | voice override jailbreak (arbitrary string in sessionConfig.audio.output.voice reaching OpenAI) | mitigate | Validate the candidate FIRST with `in_array(..., self::ALLOWED_VOICES, true)`; non-allowlisted → global voice; harness asserts malicious value rejected (Pitfall 4, CR-01 precedent) |
| T-08-10 | Tampering | prompt injection via sessionConfig.instructions override | accept | Length cap reduces blast radius; full content-filtering out of scope — a page author editing their own shortcode already has author-tier trust over their own page (RESEARCH Security Domain, accepted residual) |
| T-08-12 | Information Disclosure | rejection-reason detail aiding probing | mitigate | Silent fallback only; no distinct error code/message for rejected overrides (existing generic-error convention) |
| T-08-13 | Repudiation | regression silently re-opening D-07 gap | mitigate | No-usable-override regression harness case asserts Phase 6 global-forced output is byte-for-byte unchanged |
