<objective>
Close the single blocker gap from Phase 8 UAT Test 1: clicking "Click to talk" on the embedded WordPress avatar returns `{"error":"session_unavailable"}` instead of minting a session.

Root cause (confirmed via live curl against the real OpenAI `/v1/realtime/client_secrets` endpoint, see `.planning/debug/session-unavailable-error.md`): `OpenAIRealtimeProvider.connect()`'s `useProxy` branch unconditionally injects `temperature: this.config.temperature ?? 0.8` into the `sessionConfig` object POSTed to the proxy. OpenAI's realtime session-create schema does NOT accept a session-level `temperature` field and rejects the whole request with `400 Unknown parameter: 'session.temperature'`. The PHP layer (`OpenAiDirectTokenProvider.php`, `SessionController.php`) correctly forwards the field and correctly maps the resulting 400 to the detail-free public error (D-09) — neither PHP file is buggy and neither is touched here.

Removing `temperature` alone from the payload produced a valid 200 + ephemeral token in live reproduction. Every other field the bundle sends is accepted.

Purpose: Make the front-end embed actually connect — the core EMBED-01/EMBED-05 capability is non-functional without this one-field fix.
Output: `temperature` removed from the proxy `sessionConfig`; the construction extracted into a testable `buildProxySessionConfig()` method; a vitest regression test that asserts the field is absent; vitest infra added to the package (it currently has none).
</objective>

(packages/providers/openai-realtime/src/OpenAIRealtimeProvider.ts:139-198). Current shape:

```
  const sessionConfig: any = {
    type: "realtime" as const,
    model: this.config.model || "gpt-realtime-1.5",
    instructions: this.config.instructions || "You are a helpful AI assistant.",
    temperature: this.config.temperature ?? 0.8,   // <-- LINE 145, the bug
    output_modalities: ["audio"] as const,
    audio: {
      input: { transcription: { model: "gpt-4o-transcribe", language: this.config.language || "en" } },
      output: { format: { type: "audio/pcm" as const, rate: 24000 as const }, voice: this.config.voice || "alloy", speed: this.config.speed || 1.0 } },
  };
  // ...then conditionally appends sessionConfig.tools from this.config.tools...
  const tokenRes = await fetch(proxyEndpoint, { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ sessionConfig }) });
  // ...
}
```

RealtimeConfig (packages/core/src/types/realtime.ts) still declares `temperature?: number` (line 42) —
DO NOT remove it from the type, and DO NOT remove the constructor default at

configureSession() (line 382) builds a separate `session.update` over the data channel and does

OpenAI's realtime session schema. No other site needs changing.
