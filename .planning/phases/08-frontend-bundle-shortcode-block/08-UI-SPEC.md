# Phase 8 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — this phase has two distinct, non-shadcn UI surfaces: (1) server-rendered WP-admin markup reusing WP core's own admin CSS classes, consistent with Phase 7's `SettingsPage.php` precedent; (2) a small bespoke CSS file shipped with the bundle for the front-end avatar widget's idle/connecting/error/placeholder states. Neither surface uses React component libraries, Tailwind, or shadcn — the repo root's Tailwind config is scoped to the Next.js demo app (`src/app`) and does not apply to `wordpress-plugin/`. |
| Component library | none (WP core admin CSS for the admin notice; plain hand-written CSS + inline SVG for the front-end widget chrome) |
| Icon library | none required. The "Click to talk" affordance is text+button, not an icon. If a microphone icon is desired for the button, use a single inline SVG (no icon font/library dependency added to the bundle, keeping bundle size down per D-10's "isolated bundle, no exotic deps" spirit). |
| Font | inherit from host page (no `@font-face` shipped). The widget renders inside arbitrary WordPress themes — it must not impose a font, only set `font-family: inherit` on its own text nodes (button label, notice copy, placeholder caption) so it visually matches whatever theme it's embedded in. The WP-admin notice surface inherits wp-admin's own font stack automatically by reusing core CSS classes. |

**Assumption (not discussed in CONTEXT.md, default applied):** No shadcn gate was run because this is a PHP/WordPress phase with a vanilla-JS-bundle frontend (no React/Next.js/Vite app shell where shadcn would apply in the conventional sense — `packages/wp-bundle` is a library-style IIFE build, not an application scaffold). Per `<shadcn_gate>`, shadcn initialization only applies to React/Next.js/Vite *application* targets; this bundle wraps `@khaveeai/react` components but ships zero new shadcn-style UI primitives of its own. Documented here as an explicit, low-risk default rather than asked, per `--auto` mode.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside the "Click to talk" button; notice banner inner padding-bottom between heading and link |
| sm | 8px | Gap between the connecting-state pulse indicator and its label text |
| md | 16px | Admin notice banner padding (all sides); gap between avatar canvas and the overlay button/notice |
| lg | 24px | Padding around the logged-out placeholder silhouette image within its mount-point container |
| xl | 32px | Minimum mount-point height reserved before the avatar model finishes loading (prevents layout shift) — used as `min-height` on `.khaveeai-root` together with an explicit aspect-ratio box |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions:
- Touch target minimum for the "Click to talk" button is 44px height (accessibility floor for a primary CTA on a small-screen embed), even though 44 is not a multiple of 4 in the strict 8-pt scale — treat 44px as a fixed touch-target exception, not a new spacing token.
- The mount-point `min-height` (32px token, scaled up) is a layout-shift guard, not a literal rendered spacing value — actual avatar canvas height is responsive to its container width (typically 300-500px tall), set by the bundle's CSS, not hardcoded pixel values in this contract.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (notice copy, placeholder caption) | 14px | 400 (regular) | 1.5 |
| Label (button text: "Click to talk", "Connecting...") | 16px | 600 (semibold) | 1.2 |
| Heading (admin notice title: "Khavee AI Avatar isn't configured yet") | 16px | 600 (semibold) | 1.2 |
| Display | not used — this phase has no large display-style text; the avatar itself is the visual focal point, not typography | — | — |

Source: 14px/16px matches WP-admin's own default body/label sizing (`.notice p`, `.button` text) so the admin-facing notice visually belongs inside wp-admin without introducing a third type scale. The front-end widget's button/placeholder text reuses the same two sizes for consistency between the two surfaces, deliberately keeping this phase's full type system to 2 sizes / 2 weights (within the 3-4 size / 2 weight contract ceiling, on the lean end since the widget has very little text).

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `transparent` / inherit host page background | The avatar mount point has no opaque background of its own — it sits on whatever background the WordPress theme/page already provides at that location. This is a deliberate departure from typical 60/30/10 app-chrome color contracts, because this widget is an embed, not a standalone page. |
| Secondary (30%) | `#1e1e1e` at 55% opacity (`rgba(30,30,30,0.55)`) | The semi-transparent overlay scrim behind the "Click to talk" button and the connecting-state pulse, so button/label text stays legible regardless of the avatar's own colors or the host theme's background, per D-01/D-02 ("subtle loading indicator/pulse overlays the avatar itself") |
| Accent (10%) | `#2271b1` (WordPress core admin blue, `--wp-admin-theme-color` default) | Reserved for exactly: (1) the "Click to talk" button's background in its default/idle state, (2) the "Go to Settings" link inside the admin-only notice (D-06). Nowhere else — not used for borders, not used for the connecting-state pulse color (which uses the secondary scrim + a neutral white/light pulse, not the accent color, so "connecting" doesn't read as a second competing call-to-action). |
| Destructive | `#d63638` (WP core admin "error" red, matches `.notice-error`) | Reserved for exactly: the admin-only not-configured notice's icon/left-border accent (using WP core's own `.notice-warning` or `.notice-error` class per D-06 — see Copywriting Contract for which severity). Never applied to the logged-out visitor's placeholder (D-07 is explicitly neutral/inert, not alarming). |

Accent reserved for: the "Click to talk" button background (idle state only) and the admin notice's "Go to Settings" link. Never used for body text color, never used decoratively on the placeholder silhouette, never used for more than these two elements.

**Assumption (default applied, not explicitly discussed in CONTEXT.md):** WP core admin blue (`#2271b1`) is used as the accent specifically because D-06 mandates the admin notice "match plain WP-admin-notice conventions" — reusing wp-admin's own CSS variable keeps the button colorway consistent with the admin surface it's adjacent to on a logged-in admin's screen, without inventing a new brand color this milestone doesn't specify. If the project has an existing brand color from the Next.js demo app, it was not found in `wordpress-plugin/` and is out of scope for this PHP-plugin-only phase.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Click to talk"** — idle-state button label (D-01). Exact verb+noun per CLAUDE.md's no-emoji, plain-language convention already established in Phase 7's settings copy. |
| Connecting-state CTA | **"Connecting…"** — button becomes disabled and swaps to this label after click, before WebRTC connects (D-02). Use a real ellipsis character or three periods, no animated/decorative dots beyond the existing pulse overlay. |
| Admin not-configured notice (heading) | **"Khavee AI Avatar isn't configured yet"** |
| Admin not-configured notice (body + link) | **"Add your OpenAI API key in Settings to activate this avatar for visitors. [Go to Settings]"** — link text is "Go to Settings", target is the Phase 7 `SettingsPage.php` admin URL. Rendered using WP core's `.notice.notice-warning` class (warning, not error — the embed isn't broken, it's simply unconfigured; reserve `.notice-error` semantics for an actual runtime failure state, not the expected first-install state). Per D-06, this entire block is server-rendered PHP gated on `current_user_can('manage_options')` — it must not exist in the HTML at all for logged-out visitors, not merely be hidden by CSS. |
| Logged-out visitor placeholder (caption, optional) | No text required (D-07 specifies "no error text"). If a caption is included purely for screen-reader accessibility, use visually-hidden alt text on the silhouette image: `alt="AI avatar placeholder"` — never rendered as visible body copy, since D-07 requires the surface to read as visually inert, not as a message. |
| Error state (runtime failure, e.g. WebRTC connect fails after click) | **"Couldn't connect. [Try again]"** — shown in place of the "Connecting…" label if `connect()` rejects after the user already clicked; this is a *visitor-facing* transient error (distinct from D-06's admin-only not-configured notice), so it must stay generic — no raw error messages, stack traces, or HTTP status codes surfaced to the visitor. "Try again" re-triggers the same click-to-connect flow (D-01's explicit-gesture requirement still applies — do not auto-retry). |
| Destructive confirmation | None this phase — there are no destructive actions in the frontend bundle/shortcode/block surface (no delete/remove actions exposed to end visitors; admin-side destructive actions, if any, belong to Phase 7's settings page, already specified there). |

## Interaction States (Phase-Specific Contract)

This phase's primary UI surface is a stateful embedded widget, not a typical form/list screen — the checker should validate these states explicitly since they map directly to ROADMAP Success Criteria 1, 4, and 6:

| State | Trigger | Visual | Network/Permission Activity |
|-------|---------|--------|------------------------------|
| Idle | Page load, configured + visitor has no special role | Avatar renders in static idle pose immediately; accent-colored "Click to talk" button overlays it (D-01) | None — no mic prompt, no token request, per EMBED-05/Criterion 4 |
| Connecting | Visitor clicks the button | Secondary-scrim pulse overlays avatar; button disabled, label "Connecting…" (D-02); avatar itself never disappears, no layout shift | Mic permission prompt fires now (first user gesture); REST call to mint ephemeral token fires now |
| Active/Speaking | Token minted, WebRTC connected | Existing `@khaveeai/react` `chatStatus`-driven talking animation (no new visual contract needed — reuses `VRMAvatar`/`GLBAvatar` as-is) | Live WebRTC session |
| Editor preview (Gutenberg `edit()`) | Admin inserts/edits the block in wp-admin | Static, inert preview — same idle pose as front-end Idle state, but the "Click to talk" button is either omitted or non-interactive (decoration only) | Zero network calls to the token route, zero mic prompts, ever (EMBED-05/Criterion 4 — this is a hard requirement, not a visual nicety) |
| Admin not-configured | `is_configured()` returns false AND `current_user_can('manage_options')` | WP-admin-notice-styled banner (D-06) INSIDE the mount point, replacing the idle avatar entirely for this case | None — no avatar assets even attempt to load; this is a pure PHP early-return before the bundle's mount script has anything to do |
| Visitor not-configured | `is_configured()` returns false AND visitor lacks `manage_options` | Static neutral silhouette placeholder image (D-07), no button, no text, no console error | None |
| Runtime connect error | `connect()` rejects after Connecting state | Generic "Couldn't connect. Try again." replaces the button label; avatar stays in idle pose | None until visitor clicks "Try again", which restarts the Connecting flow |
