<objective>
Close the two UAT gaps found in Plan 09-06 and unblock UAT steps 5-14.

GAP-1 (inspector slider drag does not update preview): Gutenberg's React reconciler clobbers React 19's scene output on every Edit() re-render because the mount-point div has a virtual-DOM child (the fallback banner). Replacing the child with `dangerouslySetInnerHTML={{ __html: '' }}` stops child reconciliation, preserving React 19's output across drag events.

GAP-2 (camera preset dropdown does not reframe): R3F's `<Canvas camera={{...}}>` prop is initialization-only — subsequent prop changes are silently ignored. Adding a `CameraController` component inside `<Canvas>` that uses `useThree()` to imperatively update the live camera object (position, lookAt, fov) on every preset change fixes this.

Purpose: These two fixes restore the STUDIO-01 reactivity contract — every inspector control must produce a visible response within one frame.

Output: Two modified source files (editor.js, PreviewScene.tsx) and a blocking human-verify checkpoint that re-runs UAT steps 5-14.

    ```tsx
    // ── CameraController ─────────────────────────────────────────────────────────

    /**
     * Imperatively syncs the R3F camera to position/target/fov on every change.
     *
     * R3F's <Canvas camera={{...}}> prop is initialization-only (Pitfall 7: camera
     * prop not reactive). This component uses useThree() to access the live camera
     * object and useEffect to call camera.position.set / camera.lookAt /
     * camera.updateProjectionMatrix imperatively whenever the props change.
     *
     * Uses individual array-element deps ([pos[0], pos[1], pos[2], ...]) rather
     * than the tuple refs so the effect does not re-run when resolveSceneDefaults
     * returns a new tuple reference with identical values.
     *
     * STUDIO-02 safety: does NOT call useRealtime(), does NOT import any khaveeai
     * provider — only useThree from @react-three/fiber and THREE from three.
     */
    function CameraController({
      position,
      target,
      fov,
    }: {
      position: [number, number, number];
      target: [number, number, number];
      fov: number;
    }): null {
      const { camera } = useThree();

      useEffect(() => {
        camera.position.set(position[0], position[1], position[2]);
        camera.lookAt(target[0], target[1], target[2]);
        if (camera instanceof THREE.PerspectiveCamera) {
          camera.fov = fov;
          camera.updateProjectionMatrix();
        }
        // Individual element deps avoid re-firing when a new tuple reference
        // is created with the same values (resolveSceneDefaults returns new
        // tuple objects on every render).
        // eslint-disable-next-line react-hooks/exhaustive-deps
      }, [camera, position[0], position[1], position[2], target[0], target[1], target[2], fov]);

      return null;
    }
    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| editor.js (Gutenberg React) → mount-point div children | dangerouslySetInnerHTML with a static empty string ('') is safe: the __html value never contains user data. If __html were dynamic, XSS would be possible — this must never be changed to accept user-authored HTML. |
| preview bundle import graph → OpenAI token endpoint | CameraController must not introduce any import that reaches OpenAIRealtimeProvider, getUserMedia, or the /session endpoint. Only useThree (R3F) and THREE (three.js) are imported. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-07-01 | Tampering | dangerouslySetInnerHTML in editor.js | mitigate | The `__html` value is always the literal string `''` (hardcoded — never derived from block attributes, user input, or the DOM). No escaping needed because the value is not user-controlled. If a future change makes `__html` dynamic, a Content Security Policy + DOMPurify sanitization gate must be added before the assignment. |
| T-09-07-02 | Information Disclosure | CameraController import chain | mitigate | CameraController imports only `useThree` from `@react-three/fiber` and `* as THREE` from `three` — both are already in the preview bundle's import graph (PreviewScene.tsx uses Canvas from R3F; three.js is a transitive dep). The build.mjs safety grep (`grep -c "RealtimeProvider\|getUserMedia\|ephemeral" khaveeai-preview.js == 0`) is required to pass before the UAT checkpoint proceeds. |
| T-09-07-03 | Denial of Service | WebGL context churn from CameraController re-renders | accept | CameraController uses `useEffect` with individual element deps — it only triggers the imperative camera update, not a Canvas remount. No WebGL context is created or destroyed. Risk is negligible. |
| T-09-07-SC | Tampering | npm/pip/cargo installs | accept | This plan installs zero new packages. `useThree` is a named export already in `@react-three/fiber` (in node_modules); `three` is already a direct dependency. No package manager install commands are run. |
