<objective>
Integrate bone-masked upper-body layering into `VRMAvatar.tsx`, replacing the whole-skeleton crossfade FOR STATUS-DRIVEN KEYS ONLY (idle/listening/thinking/speaking + their variant/keyword picks), while leaving the existing full-skeleton path intact for developer-triggered custom `animate()` calls (D-04).

Purpose: Eliminate the full-body snap on every chatStatus transition — the lower body (hips/spine/legs) keeps its idle motion continuously via an always-on base action, while only the upper body crossfades to the gesture clip. This is the payload of Phase 11; it consumes Plan 01's `filterClipTracksByBoneSet` + bone-set constants.

Output: Edits to the single file `packages/react/src/VRMAvatar.tsx` — new refs, a memo, two new effects, a gate on the existing crossfade effect, and weight coordination. The `useFrame` loop's single `mixer.update(delta)` and Phase 10 procedural-delta ordering are preserved unchanged.

Explicit resolutions of the three RESEARCH open questions (surfaced here for the checker and executor):
- Open Q1 / A1 (RESOLVED = YES): any key selected from WITHIN the chatStatus auto-mapping effect — including speaking variants and keyword-matched picks, not just the four literal status names — is treated as status-driven and goes through the bone-masked upper path. Provenance is tracked via `statusDrivenKeyRef`.
- Open Q2 (RESOLVED, REQUIRED TASK — not optional): cross-path bone conflict (Pitfall 2) is fixed by zeroing `baseActionRef`/`upperActionRef` effective weight while a custom whole-skeleton key is authoritative, restoring to 1 when returning to a status-driven key.
- Open Q3 (RESOLVED): the auto-mapping effect keeps calling `animate(key)` so `currentAnimation` stays observable; the MIXER-DRIVING logic is decoupled — status keys are driven by the new upper-layer + base-lower path, and the existing whole-skeleton effect early-returns for them.
</objective>
