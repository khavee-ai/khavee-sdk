<objective>
Add a `getHumanoidBoneNode(role)` method to the `AvatarFormatAdapter` contract and implement it on both avatars, so the Wave-2 procedural systems (breathing/sway) can resolve `"chest"`/`"spine"`/`"hips"` bones reliably across every VRM rig — not just the coincidentally-named ones.

Purpose: The existing `getBoneNode(name)` is a LITERAL scene-graph lookup. This project's own default demo avatar (`male.vrm`) names its chest bone `"J_Bip_C_Chest"`, so `getBoneNode("chest")` returns `null` and breathing/sway would silently do nothing on the default avatar (RESEARCH Pitfall 1, directly verified). VRM humanoid-role resolution fixes this at the contract level, once, for both formats.
Output: Extended interface + two adapter implementations. No behavior change yet — this is the interface-first foundation Wave 2 builds against.
</objective>
