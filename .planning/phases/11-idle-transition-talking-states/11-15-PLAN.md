<objective>
Root-cause and fix G5: the visible Y-axis (hips-height) drop during the initial T-pose-to-idle settle on first page load, before Connect is pressed.

This is the fifth gap-closure round for Phase 11. Rounds 3-4 (11-11, 11-13) proved that only headless-runtime-evidence-based diagnosis succeeds here; four prior assumption-based rounds (11-06 through 11-10) failed live re-verification. 11-13's G1 fix (the base clip's first crossfade now fires at page-load time via `shouldTriggerClipSwitch`) had the side effect of relocating 11-13's already-measured hips-Y settle motion from connect-time (G3, fixed) to page-load-time (G5). The human questioned this ("shouldn't it not drop?"), signaling it reads as unwanted, not an accepted cost.

Purpose: Eliminate the visible page-load drop while preserving G1-G4 and all 7 approved requirements, using the same runtime-evidence discipline 11-11/11-13 established — measure the exact mechanism against the REAL production path before changing any behavior.

Fix-site decision (revised after plan-checker round 1): the drop's root cause is `remapMixamoAnimationToVrm` normalizing every Mixamo clip's hips-position track to start at Y=0, while the VRM's bind-pose local hips Y is ~1.008. The correct, lowest-risk fix is at the retarget source: anchor the hips track at the VRM bind-pose local hips Y instead of 0. This makes BOTH crossfade blend endpoints (the bind pose the mixer starts from, and the animation's first frame) equal, so THREE's PropertyMixer blend `original*(1-w)+animated*w` is flat at EVERY weight — sidestepping the weight-proportional math a controller-local additive correction would require, and avoiding the "pop up then settle" overshoot the checker identified in a flat-offset approach. It is also naturally VRM-scoped: GLBAvatar.tsx never calls this retargeter, so happy.glb's already-correctly-authored hips heights are untouched.
Output: A recorded diagnosis (new "11-15 gap closure" header block) plus a targeted, regression-tested fix in remapMixamoAnimationToVrm.ts.
</objective>
