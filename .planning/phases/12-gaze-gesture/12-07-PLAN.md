<objective>
Close Gap 1 from 12-06-VERIFICATION.md: the camera-relative gaze offset in `stepGaze` (`packages/react/src/animation/gaze.ts`) jumps/snaps to its target rather than smoothly interpolating toward it over time. The current `strength = Math.min(1, state.modeElapsed / RAMP_SECONDS)` is a one-shot fade-in that only resets when the `GazeMode` enum changes; because `_scratchCurrent` is re-captured from the (gaze-free) base pose every frame, once ramped the head lands exactly on the clamped target each frame with zero lag, and any mode switch snaps the head back through the neutral base before easing into the new target. Add a persistent, frame-rate-independent smoothing state so the applied gaze eases toward the target continuously.

Purpose: GAZE-01 and GAZE-02 both FAIL solely because of this snapping (human verdict: "the gaze is snap. not smooth" on VRM; "the gaze is also snap" on GLB). This is the shared root cause across both formats — one fix resolves the snapping on both.
Output: Updated `gaze.ts` with continuous smoothing; updated/extended `gaze.test.ts` proving convergence-not-snap and preserving the existing angle-bound guarantees.
</objective>
