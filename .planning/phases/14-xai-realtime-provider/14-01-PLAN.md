# Plan 14-01: xAI Realtime Provider — Full Implementation

## Objective

Create `@khaveeai/providers-xai-realtime` — a new provider package implementing `RealtimeProvider` over xAI's WebSocket-based Realtime API, with identical lip-sync/audio-analysis behavior to `OpenAIRealtimeProvider`.

## Context

xAI's Realtime API uses **WebSocket** (not WebRTC). Audio is sent/received as base64-encoded PCM in JSON messages. The event schema is ~95% compatible with OpenAI's. The critical requirement is that `getAudioAnalyser()` returns an `AnalyserNode` with identical settings (fftSize=2048, smoothingTimeConstant=0.6) so the React layer's MFCC/DTW phoneme detection drives lip-sync identically.

### Task 3: AudioPlaybackEngine — Streaming PCM Playback + AnalyserNode

<read_first>
- packages/providers/openai-realtime/src/OpenAIRealtimeProvider.ts (lines 905-967 — setupAudioOutputAnalysis + getAudioAnalyser)
- packages/providers/openai-stt-tts/src/TTSPlayer.ts (lines 100-130 — dual-path audio routing)
</read_first>

<action>
Create `src/AudioPlaybackEngine.ts`:

A class that:
1. Creates an AudioContext (lazily, on first audio chunk)
2. Creates an AnalyserNode with **exactly**: `fftSize = 2048`, `smoothingTimeConstant = 0.6`
3. Receives base64-encoded PCM16 chunks via `appendChunk(base64: string)`
4. Decodes each chunk: base64 → ArrayBuffer → Int16Array → Float32Array (÷32768)
5. Creates an AudioBuffer from the float samples (mono, sampleRate from config, default 24000)
6. Schedules playback using queued AudioBufferSourceNodes with precise `start(nextTime)` timing
7. Audio routing: each source → GainNode → split to (AnalyserNode) AND (AudioContext.destination)
8. Exposes `getAnalyser(): { analyser: AnalyserNode, audioContext: AudioContext } | null`
9. Tracks playing state: `isPlaying: boolean` (true from first chunk scheduled to last buffer ended)
10. Emits callbacks: `onPlaybackStart()`, `onPlaybackEnd()` (when all queued buffers finish)
11. `cancel()` method: stops all scheduled sources, resets queue (for barge-in/interrupt)
12. `destroy()` method: closes AudioContext if state !== "closed"

Key implementation detail: maintain `nextScheduledTime` starting at `audioContext.currentTime + small latency buffer (0.05s)`. Each new chunk is scheduled at `nextScheduledTime`, then `nextScheduledTime += chunk.duration`. This produces gapless streaming playback.
</action>

<acceptance_criteria>
- `AudioPlaybackEngine` class exists with methods: `appendChunk`, `cancel`, `destroy`, `getAnalyser`
- AnalyserNode settings are exactly `fftSize=2048`, `smoothingTimeConstant=0.6`
- Audio routing: source → GainNode → AnalyserNode (analysis path) AND → destination (playback path)
- `onPlaybackStart` fires on first chunk, `onPlaybackEnd` fires when all buffers complete
- `cancel()` stops all scheduled AudioBufferSourceNodes
</acceptance_criteria>

### Task 4: MicCaptureEngine — PCM Recording + Base64 Encoding

<read_first>
- packages/providers/openai-stt-tts/src/AudioRecorder.ts (VAD-based mic capture pattern)
- packages/providers/openai-realtime/src/OpenAIRealtimeProvider.ts (lines 600-650 — mic stream management)
</read_first>

<action>
Create `src/MicCaptureEngine.ts`:

A class that:
1. Requests mic via `navigator.mediaDevices.getUserMedia({ audio: { sampleRate: 24000, channelCount: 1 } })`
2. Creates an AudioContext + MediaStreamSource from the mic stream
3. Uses an AudioWorkletNode (registered from `pcm-capture-processor.ts`) to capture raw PCM samples in 4096-sample frames
4. The worklet's `process()` copies input samples to a port message
5. On each frame from the worklet: convert Float32Array → Int16Array (×32767, clamp) → base64 string
6. Emits `onAudioFrame(base64: string)` callback with each encoded frame
7. `enable()` / `disable()` — starts/stops the worklet processing (tracks are kept alive for fast re-enable)
8. `destroy()` — stops all tracks, closes AudioContext
9. Exposes `isEnabled: boolean` and the raw `MediaStream` for potential reuse

Also create `src/pcm-capture-processor.ts` — the AudioWorklet processor:
- Registered as `"pcm-capture-processor"`
- `process(inputs)`: copies input[0][0] (mono) to `this.port.postMessage()`
- Returns `true` to keep processing
</action>

<acceptance_criteria>
- `MicCaptureEngine` exists with methods: `enable`, `disable`, `destroy`, property `isEnabled`
- `onAudioFrame` callback fires with base64-encoded PCM16 string
- `pcm-capture-processor.ts` registers a worklet named `"pcm-capture-processor"`
- `disable()` stops sending frames, `enable()` resumes
- `destroy()` calls `track.stop()` on all mic tracks and closes AudioContext
</acceptance_criteria>

### Task 5: XAIRealtimeProvider — Core WebSocket Connection + Session Management

<read_first>
- packages/core/src/types/realtime.ts (full RealtimeProvider + RealtimeEvents interfaces)
- packages/providers/openai-realtime/src/OpenAIRealtimeProvider.ts (lines 150-250 — connect/disconnect pattern)
- packages/providers/openai-realtime/src/OpenAIRealtimeProvider.ts (lines 60-90 — state fields)
</read_first>

<action>
Create `src/XAIRealtimeProvider.ts` implementing `RealtimeProvider`:

**State fields:**
- `private ws: WebSocket | null = null`
- `private playbackEngine: AudioPlaybackEngine | null = null`
- `private micEngine: MicCaptureEngine | null = null`
- `private config: XAIRealtimeConfig`
- `private conversation: Conversation[] = []`
- `private messages: ChatMessage[] = []` (LLM history)
- `private chatStatus: ChatStatus = "ready"`
- `private micEnabled = false`
- `private isConnected = false`
- `public currentVolume = 0`

**Event callbacks (from RealtimeEvents):**
- `onConnect`, `onDisconnect`, `onMessage`, `onError`, `onChatStatusChange`
- `onAudioData`, `onAudioStart`, `onAudioEnd`, `onVolumeChange`
- `onMouthStateChange`, `onPhonemeDetected`
- `onUsageReport`

**connect(config):**
1. If `config.tokenEndpoint` — fetch ephemeral token from backend first
2. Build WebSocket URL: `${baseUrl}?model=${model}`
3. Connect with auth: `new WebSocket(url, ["xai-client-secret." + token])` (ephemeral) OR set Authorization header via url params for API key mode
4. On `ws.open`: send `session.update` event with voice, instructions, tools, turn_detection, input_audio_format, output_audio_format
5. Set `isConnected = true`, fire `onConnect?.()`
6. Initialize `AudioPlaybackEngine`
7. Initialize `MicCaptureEngine`, wire `onAudioFrame` → send `input_audio_buffer.append`

**disconnect():**
1. Send close frame on WebSocket
2. `micEngine.destroy()`, `playbackEngine.destroy()`
3. Set `isConnected = false`, fire `onDisconnect?.()`

**WebSocket message handler (onmessage):**
Route by `event.type`:
- `session.created` / `session.updated` — confirm session ready
- `input_audio_buffer.speech_started` — setChatStatus("listening")
- `input_audio_buffer.speech_stopped` — (VAD detected end of speech)
- `input_audio_buffer.committed` — user turn committed
- `conversation.item.created` — add to conversation array
- `conversation.item.input_audio_transcription.updated` — update user transcript (cumulative, not delta)
- `response.created` — setChatStatus("thinking")
- `response.output_item.added` — new output item (text or audio)
- `response.content_part.added` — content part started
- `response.text.delta` — append text to current response
- `response.text.done` — text response complete
- `response.audio.delta` (or `response.output_audio.delta`) — feed to playbackEngine.appendChunk()
- `response.audio.done` (or `response.output_audio.done`) — mark audio complete
- `response.function_call_arguments.delta` — accumulate tool args
- `response.function_call_arguments.done` — execute tool, send result back
- `response.done` — finalize response, setChatStatus("ready")
- `error` — fire onError

**setChatStatus(status):**
- Update `this.chatStatus`
- Fire `onChatStatusChange?.(status)`
- On "speaking": fire `onAudioStart?.()`, fire `onAudioData?.(analyser, audioContext)` ONCE (first time only)
- On transition away from "speaking": fire `onAudioEnd?.()`
</action>

<acceptance_criteria>
- `XAIRealtimeProvider` implements `RealtimeProvider` from `@khaveeai/core`
- `connect()` opens WebSocket to `wss://api.x.ai/v1/realtime?model=...`
- `connect()` sends `session.update` after connection opens
- `disconnect()` closes WebSocket + destroys audio engines
- All server event types are routed and handled
- `setChatStatus` fires `onChatStatusChange` + audio start/end callbacks
- `onAudioData` fires exactly once with `(analyser, audioContext)` on first speaking
- `tsc --noEmit` passes with zero type errors
</acceptance_criteria>

   - Clear from pendingToolArgs

**Session update tool format:**
Tools are sent in `session.update` as:

Same schema as OpenAI's function tools.

## must_haves

### truths (what must be TRUE for the phase goal to hold)
- XAIRealtimeProvider implements RealtimeProvider identically to OpenAIRealtimeProvider from the React layer's perspective
- AnalyserNode is created with fftSize=2048 and smoothingTimeConstant=0.6
- onAudioData fires once with (analyser, audioContext) on first audio chunk
- getAudioAnalyser() returns the same shape { analyser, audioContext } as OpenAI provider
- Microphone capture produces base64 PCM16 frames sent as input_audio_buffer.append
- Tool calling follows the same register→receive→execute→respond flow as OpenAI

### absences (what must NOT exist)
- No dependency on RTCPeerConnection or WebRTC APIs
- No hardcoded API keys in the provider (ephemeral token or backend proxy pattern only)
- No breaking changes to @khaveeai/core types
- No modifications to existing openai-realtime provider
- No AnalyserNode connected directly to AudioContext.destination (analysis-only path)
