<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote `.vrm`/texture asset → renderer | A `VRMAvatar` `src` may be a third-party URL; its textures become `THREE.Texture` objects this pass samples |
| `averageTextureColor` → 2D canvas readback | Cross-origin texture data crossing into `getImageData` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-01 | Information Disclosure | `averageTextureColor` Path B | mitigate | `getImageData` on a canvas tainted by a cross-origin texture throws `SecurityError`; the whole browser path is wrapped in try/catch returning `null`. The function never reads pixel data it is not permitted to read, and never surfaces raw texel data — only a single averaged colour used as a rim tint. |
| T-15-02 | Denial of Service | `averageTextureColor` Path A | mitigate | Path A averages the full texel buffer of an attacker-supplied texture. Bounded by the asset already being fully decoded in memory; the readback canvas in Path B is fixed at 16x16 regardless of source size, so the browser path is O(1) in destination pixels. |
| T-15-03 | Tampering | `repairMToonMaterials` mutating shared materials | accept | The pass mutates `MToonMaterial` instances owned by the caller's own scene graph. `snapshotMToon`/`restoreMToon` make the mutation reversible; `VRMAvatar` loads a per-instance VRM (see `useLoadVRM`), so no cross-instance material sharing exists. |
| T-15-SC | Tampering | npm installs | accept | This plan adds no new dependencies — `three` and `@pixiv/three-vrm` are already direct dependencies of `@khaveeai/react`. No package-manager install task exists, so no legitimacy gate applies. |
</threat_model>
