<decisions>
- **Separate test file.** Real-asset tests live in `mtoonRepair.assets.test.ts`, not in
  `mtoonRepair.test.ts` (Plan 01's synthetic unit tests). Reason: the asset tests import `node:fs`
  and parse ~50 MB of GLB, needing a raised timeout; keeping them separate means the fast synthetic
  suite stays fast and the node-only imports sit in one clearly-named file.
- **How `packages/react` tests reach the assets.** By relative path from the test file to the
  monorepo's playground public directory:
  `fileURLToPath(new URL("../../../../apps/playground/public/models/", import.meta.url))`
  (`src/utils` -> `src` -> `react` -> `packages` -> repo root). No copying, no fixtures, no new
  dependency. The assets are committed to the repo, so this resolves in CI as well as locally.
- **Missing assets fail loudly.** If a `.vrm` file is absent the test throws with the resolved path
  in the message rather than silently skipping. A silently-skipped invariant is worse than no
  invariant.
</decisions>
