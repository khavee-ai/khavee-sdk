<decisions>
- **`debugShading` uses the runtime setter, not the load-time plugin option** (15-RESEARCH §6,
  open question 1 — RESOLVED). Verified against the installed
  `@pixiv/three-vrm-materials-mtoon@3.4.2` lib source: `set debugMode(m)` assigns `_debugMode` and
  then sets `this.needsUpdate = true`, which triggers a shader recompile with the
  `DEBUG_LITSHADERATE` define. `MToonMaterialLoaderPlugin`'s `debugMode` option is load-time only
  and would force a full model re-parse to toggle. The prop therefore drives
  `setMToonDebugMode(scene, ...)` from an effect.
- **`materialPreset` ships as `"off" | "repair"` only; `"anime-premium"` is DEFERRED**
  (15-RESEARCH §6, open question 2 — RESOLVED). Two reasons: (a) only `"off"` and `"repair"` have
  spike evidence — spikes 002/003 measured and human-verified exactly those two states, and an
  unmeasured third preset would ship on vibes; (b) an "anime-premium" preset by definition
  OVERRIDES well-authored values, which contradicts this phase's locked "repair, not override"
  semantics and would break the non-regression guarantee of success criterion 2. The prop is a
  string union, so adding a third member later is a non-breaking change. This is a scope decision
  about an unproven idea, not a reduction of any locked decision.
- **Only `VRMAvatar`'s tone-mapping default changes; `GLBAvatar` keeps `ACESFilmicToneMapping`.**
  Spike 003 measured MToon/toon output only. `GLBAvatar` renders plain glTF PBR (`happy.glb`), the
  workload ACES is designed for, and the CONTEXT explicitly places `happy.glb` out of scope. Both
  components call the same Canvas-global `applyRendererDefaults`, so mounting both in one Canvas
  means last-effect-wins — this is pre-existing behaviour, not introduced here, and gets documented
  in both files rather than silently changed.
- **`applyRendererDefaults` runs regardless of `autoLighting`.** `khavee-app` mounts `VRMAvatar`
  with `autoLighting={false}` and therefore WILL still receive the new Cineon default. That is
  intended (the whole point of TONE-01), and the escape hatch is the existing `toneMapping` prop.
  It must be called out in the SUMMARY as a downstream-visible change.
</decisions>
