<decisions>
- **RESOLVED — `postprocessing` is declared as an explicit dependency of `packages/react`.** The
  open question was: import `ToneMappingMode` from a transitive package (the WR-03 class of problem
  Phase 15 hit), or hardcode its numeric value. Declaring it wins on three counts. (1) It matches
  this package's existing convention — `@react-three/drei`, `@react-three/fiber` and
  `@react-three/postprocessing` are all already plain `dependencies` here, not peers, so there is no
  established "keep vendor libs out of package.json" rule to violate. (2) A hardcoded `6` for
  `CINEON` is exactly the "magic enum index" the phase brief forbids without justification, and the
  justification would have to be re-verified on every `postprocessing` bump, with a silent wrong-curve
  failure if the enum ever gains a member — the same silent-regression shape as the D-13 defect this
  plan exists to fix. (3) `postprocessing` is already resolved once in the workspace at 6.37.8;
  declaring `^6.37.8` reuses that store entry rather than adding a second copy. Two copies would be a
  genuine defect (duplicate effect/`three` registries), so Task 1 asserts single resolution.
- **The public prop is a local string union, the enum is internal only.** `AvatarToneMapping`
  mirrors `MToonDebugMode`'s precedent exactly: Phase 15 shipped `setMToonDebugMode` taking a
  `@pixiv/three-vrm` enum consumers could not import, and had to replace it. `ToneMappingMode`
  appears in exactly one place — a private `const TONE_MAPPING_MODES: Record<...>` map — and is
  never named in an exported signature.
- **`toneMapping` defaults to `"cineon"`, matching `VRMAvatar`.** `AvatarPostFX` is a Canvas-level
  sibling and cannot know which avatar component is in the scene. Cineon is the default because
  `VRMAvatar` is the primary path and Phase 15's TONE-01 chose it. A Canvas containing only
  `GLBAvatar` should pass `toneMapping="aces-filmic"`; this is documented on the prop rather than
  inferred, because inferring it would mean reading `gl.toneMapping` at a moment when
  `EffectComposer` may already have overwritten it with `NoToneMapping` — reading the very value
  this fix exists to stop trusting.
- **`toneMapping="none"` appends no `ToneMapping` effect at all.** That is the escape hatch for a
  caller who wants the pre-fix behaviour or manages tone mapping themselves. It is not mapped to
  `ToneMappingMode.LINEAR`, because `LINEAR` is a curve and `"none"` means "do not add a pass".
- **`AvatarPostFX` still renders `null` when nothing is enabled.** The trailing `ToneMapping` is
  appended only to a composer that is already being mounted for another reason. Mounting a composer
  purely to tone-map would add a full-screen pass to consumers who asked for nothing, and the
  renderer-level curve already works correctly when no composer exists.
- **Effect order: DepthOfField → Bloom → HueSaturation → BrightnessContrast → Vignette → SMAA →
  ToneMapping.** DOF first because it operates on the depth buffer and must see un-bloomed geometry;
  grading and vignette after bloom so they act on the composed image; `ToneMapping` strictly last per
  RESEARCH Pattern 2.
- **`bloomThreshold`'s JSDoc is now wrong and must be corrected in the same task.** It currently says
  luminance is measured *after* tone mapping. Under the fixed chain, Bloom runs *before* the trailing
  `ToneMapping` pass, so it samples un-tone-mapped values and will read as more eager than the old
  text implies. Leaving the stale sentence would be a documented-behaviour contradiction inside the
  very file this plan is fixing.
- **DOF defaults are the spike-measured ones, not conservative ones.** `bokehScale: 20` and
  `worldFocusRange: 0.6` are the values spike 004 confirmed read correctly; the spike also found the
  library default of `6` indistinguishable from off at this scene scale, i.e. a timid default reads
  as "DOF is broken". DOF is opt-in, so a strong default when explicitly requested is the right
  trade.
- **Subject tracking graduates the spike's shape verbatim: React state, 0.02 world-unit threshold.**
  The ref-poking alternative (writing straight into the effect's circle-of-confusion material) would
  avoid a re-render but is not what spike 004 validated. The threshold means state only updates when
  the camera actually moves, which is what kept the measurement cheaper than the effect it measures.
</decisions>
