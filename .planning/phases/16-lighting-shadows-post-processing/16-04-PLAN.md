<decisions>
- **The backdrop renders as a sibling of the avatar's transform group, not inside it.** Both avatar
  components return a single `<group position rotation scale>`; `VRMAvatar`'s default rotation is
  `[0, Math.PI, 0]`, so a backdrop mounted inside that group would be rotated 180° away from the
  camera. Both components therefore return a fragment containing the backdrop and then the group.
- **Default-on means "supplied ⇒ composited", with no second flag.** D-07. There is no
  `backdropEnabled` prop. `background === undefined` is the entire opt-out and is the state every
  current consumer — khavee-app included — is in today, so this ships non-breaking.
- **A `COLOR` background renders the same plane with a flat `meshBasicMaterial color`.** It is
  tempting to set `scene.background` for the colour case, but then the colour would sit at infinite
  depth and DOF could not touch it, while the image case sat at a finite distance — two different
  depth behaviours behind one prop. One plane, one depth, one behaviour.
- **Rim derivation for a `COLOR` background skips sampling entirely.** Spike 007 found all four
  derivations agree trivially on a flat colour. The hook returns the colour as-is; no canvas, no
  async, no failure mode.
- **Caller-specified `lighting.rim.color` always beats the derived colour.** `mergeRimColor` only
  fills an unset rim colour. An explicit prop is an instruction, not a hint.
- **Readback is bounded to a 128px long edge, and that bound is load-bearing, not incidental.** It
  caps the per-derivation work regardless of what the customer uploaded, and plan 16-01's adversarial
  test fixture is built at 128×128 for exactly this reason — the assertion holds at the resolution
  the shipping path actually samples. A saturated region smaller than roughly 1% of the frame will
  be averaged away by the downsample; that is a documented limit, consistent with spike 007's
  instruction to document the evenly-opposed-hues class of limit rather than tune against it.
- **`crossOrigin = "anonymous"` is set on both the sampling image and the backdrop texture.** Not
  only to keep the sampling canvas untainted: WebGL's `texImage2D` also refuses a cross-origin image
  without CORS headers, so the backdrop itself already requires it. A background host that serves no
  CORS headers cannot be used in-canvas at all — that is a real adoption constraint for khavee-app's
  storage/CDN and must be stated in the prop's JSDoc, not discovered in production.
- **Failures degrade, they do not throw.** A rejected URL scheme, a failed load, or an oversized
  image reports through `onError` (normalised with the repo's
  `error instanceof Error ? error : new Error(String(error))` pattern) and leaves the rim on the
  rig's static default and the backdrop unrendered. The alternative — a thrown error inside a
  `useEffect` in someone's Canvas — takes down the whole scene over a wallpaper.
</decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| customer-supplied background image URL → SDK | A per-project customer setting (`backgroundImageUrl`) becomes an image fetched by the SDK, uploaded to the GPU as a texture, and read back pixel-by-pixel on a 2D canvas. This is the first time in the SDK's history that customer-controlled remote content is decoded and inspected in-process. |
| remote image host → browser canvas | Cross-origin content crosses into a canvas whose pixels the SDK then reads. |
| consumer app → `background` prop | Arbitrary strings reach a URL loader, a colour parser and world-space plane placement. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-12 | Information Disclosure | canvas readback of a cross-origin background image | mitigate | Reading pixels from a cross-origin image is exactly the canvas-tainting attack browsers exist to stop: without CORS the SDK could otherwise be pointed at an authenticated same-user resource and made to leak its average colour. `crossOrigin = "anonymous"` is set on both the sampling `Image` and the `TextureLoader`, so a host that does not opt in via CORS headers simply fails to load, and the `getImageData` call is wrapped in `try/catch` to handle the `SecurityError` path explicitly rather than letting it surface as an unhandled effect error. The derived value is a 3-channel average that is only ever rendered back into the same customer's own scene — never persisted, never transmitted. |
| T-16-13 | Denial of Service | attacker-supplied texture dimensions | mitigate | A decode-bomb (a small file declaring 30000×30000) exhausts memory before any SDK code runs on the pixels. The loaded image's `width * height` is checked against a 50-megapixel ceiling before it is drawn or uploaded to the GPU; over-limit images are rejected through `onError`. Independently, readback is downsampled to a 128px long edge, so derivation cost is constant regardless of source size. |
| T-16-14 | Tampering | `background.url` scheme | mitigate | The URL is fed to an image loader and must be constrained to `http:`, `https:`, `blob:` and `data:` URLs with an `image/` media type. `javascript:` will not execute from an `img.src`, but `file:` and unexpected schemes are rejected rather than probed, and the allowlist is defined once and shared by the backdrop and the sampler so the two cannot drift apart. |
| T-16-15 | Denial of Service | GPU texture lifetime | mitigate | Each background change allocates a new `THREE.Texture`. Without explicit `dispose()` in the effect cleanup, a consumer whose customer flips between background images leaks a GPU allocation per change until context loss. Disposal on URL change and on unmount is required by Task 1 and asserted by its grep. |
| T-16-16 | Repudiation | silent background failures | mitigate | A background that silently does not appear is indistinguishable from a misconfigured app. Every rejection path (scheme, size, load failure, tainted canvas) reports through `onBackgroundError`, normalised with the repo's `error instanceof Error ? error : new Error(String(error))` pattern, so a consumer can log or surface it. |
| T-16-17 | Information Disclosure | canvas screenshots now contain the backdrop | accept | Production captures screenshots from a `preserveDrawingBuffer` Canvas that was previously transparent behind the avatar. With a backdrop mounted, those screenshots now include the customer's background image. This is the intended consequence of compositing in-canvas (D-06) and the image is the customer's own, but it changes what a screenshot contains and is documented on the prop so the change is not discovered downstream. |
| T-16-18 | Tampering | `background.value` colour string | accept | Handed to three.js's colour parser; unparseable values leave the material white. Never reaches DOM, CSS or shader source. |
| T-16-SC | Tampering | npm/pnpm installs | accept | No new dependencies. `three` and `@react-three/fiber` are already declared dependencies of `@khaveeai/react`. |
</threat_model>
