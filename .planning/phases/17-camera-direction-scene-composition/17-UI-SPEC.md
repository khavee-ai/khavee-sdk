# Phase 17 — UI Design Contract

> Visual and interaction contract for the Camera Direction & Scene Composition phase. Generated by gsd-ui-researcher.

This contract covers a **pure 3D component** (`<AvatarCamera>`) with no traditional UI surface (no forms, no buttons, no text). The "design contract" here is:

- **Component API** — TypeScript props interface for `<AvatarCamera>`

- **Animation/Transition** — Easing curves and durations
- **Drift Parameters** — Procedural noise settings for camera life
- **Orbit Constraints** — Polar/azimuth/distance ranges for constrained mode

All decisions below are pre-populated from `17-CONTEXT.md` (locked by user during discussion phase).

## Component API Contract

The TypeScript interface for `<AvatarCamera>` (the single deliverable of this phase). Pre-populated from CONTEXT.md decisions D-01 through D-12.

### Props Interface

```typescript
export interface AvatarCameraProps {
  /**
   * Framing preset. Controls the base camera position, target, and FOV.
   * Runtime-swappable with smooth eased transition.
   * (D-03, D-06)
   */
  preset?: "bust-shot" | "medium-close-up" | "full-body";
  
  /**
   * Override the preset's camera position. Explicit prop overrides preset's
   * default for this axis only.
   * (D-04)
   */
  position?: [x: number, y: number, z: number];
  
  /**
   * Override the preset's camera target (lookAt point).
   * (D-04)
   */
  target?: [x: number, y: number, z: number];
  
  /**
   * Override the preset's field of view (degrees).
   * (D-04)
   */
  fov?: number;
  
  /**
   * Orbit interaction mode.
   * - "locked": Camera is fixed to preset position. No user interaction.
   * - "constrained": User can orbit within clamped ranges.
   * - "free": Unconstrained orbit (debug/dev only).
   * (D-05)
   */
  orbit?: "locked" | "constrained" | "free";
  
  /**
   * Enable/disable handheld drift (procedural noise on camera position/target).
   * Drift is always on across all chatStatus values, pauses during active
   * user orbit.
   * (D-07, D-08, D-09)
   */
  drift?: boolean;
  
  /**
   * Enable/disable state-driven reframing (dolly-only push-in on speaking,
   * ease back on listening/ready).
   * (D-10, D-11)
   */
  reframe?: boolean;
}
```

### Defaults (D-12: both drift and reframe on by default)

```typescript
const defaultProps: Required<AvatarCameraProps> = {
  preset: "bust-shot",
  position: undefined,  // Use preset's default
  target: undefined,    // Use preset's default
  fov: undefined,       // Use preset's default
  orbit: "locked",
  drift: true,
  reframe: true,
};
```

## Animation & Transition Specifications

Pre-populated from CONTEXT.md. Exact durations/curves are **Claude's discretion** within the documented ranges.

### Preset Transition (D-06)

When the `preset` prop changes at runtime:

| Property | Value | Source |
|----------|-------|--------|
| Easing curve | `easeInOutCubic` | CONTEXT.md D-06; matches Phase 10's crossfade curve for consistent cinematographic feel |
| Duration | 0.8–1.5s (TBD by executor) | CONTEXT.md D-06; tune for "smooth enough to read as deliberate, fast enough not to feel sluggish" |
| Interpolation | Linear interpolation of position/target/fov each frame | Standard R3F `useFrame` pattern |

**Behavior:** Transition fires immediately on `preset` prop change. User orbit input during transition is allowed (orbit mode permitting) and overrides the eased path — the transition is not a blocking animation.

### State-Driven Reframing (D-10, D-11)

Dolly-only (distance changes, no angle/target change):

| Trigger | Behavior | Duration | Easing |
|---------|----------|----------|--------|
| `chatStatus` → `"speaking"` | Push in ~5–10% closer to avatar | TBD (likely 0.6–1.0s) | `easeInOutCubic` |
| `chatStatus` → `"listening"` or `"ready"` | Ease back to base preset distance | TBD (likely 0.6–1.0s) | `easeInOutCubic` |

**Integration:** Reframe reads `chatStatus` from `useKhavee()` context (same source the animation layer already uses). Reframe is additive to preset distance: `effectiveDistance = presetDistance * reframeMultiplier(chatStatus)`.

## Drift Parameters (Handheld Camera Life)

Pre-populated from CONTEXT.md D-07, D-08. Exact parameters are **Claude's discretion** — tune for "subtle enough to not notice consciously, obvious enough that removing it makes the scene feel dead."

### Noise Settings

| Parameter | Value (TBD by executor) | Usage |
|-----------|-------------------------|-------|
| Noise type | Perlin or simplex (executor chooses) | Organic camera motion, not sine-based (see CONTEXT.md code insights) |
| Frequency | TBD (likely ~0.1–0.3 Hz) | Low frequency for slow drift; high frequency reads as jitter, not life |
| Amplitude (position) | ~0.5–2 cm world-space (TBD) | Applied to camera position X/Y/Z independently |
| Amplitude (target) | ~0.5–1.5 cm world-space (TBD) | Applied to camera target X/Y/Z independently; should be lower than position to avoid "wander" |

### Behavior Rules (D-08)

| Rule | Behavior |
|------|----------|
| Always on | Drift runs across all `chatStatus` values (ready, listening, speaking, thinking, starting, stopped) |
| Pauses during user orbit | Drift freezes when user is actively dragging/scrolling in `"constrained"` or `"free"` orbit mode |
| Resumes after orbit | Drift resumes smoothly (no snap) once user input ends |

**Implementation note:** Drift should use `useFrame` with time-based noise (not frame-count-based) so drift speed is independent of frame rate.

## Orbit Constraint Specifications

Pre-populated from CONTEXT.md D-05. Exact ranges are **Claude's discretion** — must keep the avatar framed from flattering angles only.

### Constrained Mode (`orbit="constrained"`)

Guidance for executor:
- Clamps must prevent "view from below", "extreme side profile that clips face", "zoomed out to infinity".
- Should feel like "you can look around the avatar but can't ruin the framing."
- Likely varies per preset (full-body allows wider orbit than bust-shot).

| Constraint | Suggested Range (TBD by executor) | Notes |
|------------|-----------------------------------|-------|
| Polar angle | ~45° – 90° (horizon to slightly above) | Prevent viewing from above or below |
| Azimuth angle | ~±60° – ±90° from front | Allow left/right orbit but not full 360° (back of head is unflattering) |
| Distance | presetDistance ± 20–30% | Allow zoom in/out but prevent "too close" or "lost in space" |

### Free Mode (`orbit="free"`)

No constraints. Equivalent to drei's `OrbitControls` default behavior. For dev/debug only, per CONTEXT.md D-05.

### Locked Mode (`orbit="locked"`)

No user interaction. Camera is fixed to the computed position (preset + drift + reframe).

## Verification Checklist (for human checkpoint)

At plan completion, the following must be verifiable by a human reviewer:

### Objective (code-level)

- [ ] `<AvatarCamera>` exported from `@khaveeai/react` with full TypeScript props interface
- [ ] All three presets (`bust-shot`, `medium-close-up`, `full-body`) render the avatar framed and visible
- [ ] Preset transitions use `easeInOutCubic` and animate smoothly (grep confirms, or visible in code)
- [ ] Drift uses time-based noise (not frame-count), pauses during user orbit, resumes after
- [ ] Reframe reads `chatStatus` from `useKhavee()` and applies dolly-only (not full reframe)
- [ ] `orbit="locked"` prevents all user interaction
- [ ] `orbit="constrained"` clamps polar/azimuth/distance (ranges documented in code comments)
- [ ] `orbit="free"` allows unconstrained orbit
- [ ] Existing `AvatarBackdrop`, `SubjectFocusTracker`, and `gaze.ts` still work (no jitter, no lag)

### Subjective (human pass/fail)

- [ ] **Preset framing:** All three presets frame the avatar deliberately (not cut off, not too far, not unflattering angle)
- [ ] **Preset transitions:** Changing `preset` at runtime feels smooth and cinematic (not mechanical or sluggish)
- [ ] **Drift:** With `drift={true}`, the camera shows subtle life; with `drift={false}`, it feels static
- [ ] **Reframe:** Triggering speaking visibly pushes in slightly; returning to ready/listening eases back
- [ ] **Constrained orbit:** User can orbit in constrained mode but cannot land on an unflattering angle
- [ ] **No regression:** Existing lighting, shadows, DOF, and backdrop still look correct with `AvatarCamera` active
