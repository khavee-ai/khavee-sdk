**Two more bugs found during the human-verify checkpoint itself** (i.e., the checkpoint did its job): the sidebar's "Global default" resolved-value display initially showed the generic fallback instead of the real number. Root causes:
1. `window.khaveeaiGlobalConfig` was read once at module-parse time, but the localized inline `<script>` (attached to the sibling `khaveeai-preview` handle) executes *after* this file's own `<script>` tag in document order — so the constant permanently captured `{}`. Fixed by reading it lazily at component-render time instead.
2. `wp_localize_script()` stringifies every value (`"1.5"`, not `1.5`) — the original `typeof === 'number'` check silently always failed. Fixed with defensive `parseFloat()`.
3. `container_width`/`container_height` are present in `get_runtime_config()` as `0` (not absent), and `0` is the same "unset" sentinel used everywhere else — `hasGlobalValue` now requires `> 0`.
