## What was built

A site-wide floating chat launcher for the Khavee WordPress plugin: an admin
toggle in Settings turns on a fixed bottom-right launcher button that appears
on every front-end page (independent of any block/shortcode placement) and
expands into a 360x520 panel containing the real avatar scene, click-to-talk
CTA, chat transcript, and mic control — all wired to the site's global config.

### Task 1 — Frontend bundle (commit `55cb37d`)

- `packages/wp-bundle/src/config.ts`: added `floating?: boolean` to
  `KhaveeAvatarConfig` with JSDoc explaining containerWidth/Height/fullWidth
  are ignored in this mode.
- `packages/wp-bundle/src/mount.tsx`: exported the previously-local
  `AvatarScene` function; `AppRoot` now branches to
  `<FloatingWidget config={config} />` when `config.floating === true`,
  skipping `containerStyle` application entirely in that branch. The
  non-floating inline-embed layout is untouched. `mountAvatarInstance`'s
  `OpenAIRealtimeProvider`/`KhaveeProvider` construction is unchanged —
  `FloatingWidget` renders as a child of the same provider tree, so
  `useRealtime()`/`useKhavee()` work normally inside it.
- `packages/wp-bundle/src/floating/FloatingWidget.tsx` (new): local
  `useState(false)` `isOpen` toggle; renders the real `AvatarScene` +
  `ClickToTalkOverlay` + `ErrorOverlay` in the avatar area, `ChatBox`
  (`placement="below"`) in the chat slot, and `ControlBar` (mic mute/unmute;
  chat toggle wired as a no-op since the launcher/close button already
  governs panel visibility) — no new business logic, purely a layout wrapper
  around already-working pieces, matching the plan's explicit
  "NOT a rebuild" framing.
- `packages/wp-bundle/styles.css`: appended a `khaveeai-floating-` prefixed
  section ported verbatim (colors/dimensions/transitions) from the approved
  mockup — solid `#6929ff`, `#dde1ea` border, `20px` radius, `220ms
  cubic-bezier(0.2,0.8,0.2,1)` transform transition, `prefers-reduced-motion`
  and `max-width:480px` media queries included. Zero `box-shadow`/`gradient`
  CSS properties anywhere in the file.
- Rebuilt `wordpress-plugin/build/khaveeai-bundle.{js,css}` and
  `khaveeai-preview.css` via `pnpm --filter @khaveeai/wp-bundle build` and
  committed the output (this repo tracks build artifacts, not `.gitignore`d).

### Task 2 — PHP (commit `6c3f532`)

- `wordpress-plugin/includes/Admin/SettingsPage.php`: new
  `render_floating_widget_field()` checkbox renderer (mirrors
  `render_remove_key_field()`'s pattern but is durably persisted, not a
  one-shot removal flag); a new "Floating Widget" section added to
  `render_page()` immediately after "Avatar"; `sanitize_settings()` persists
  `floating_widget_enabled` via strict `isset() && '1' === (string)` coercion
  (T-77n-02); also registered via `add_settings_field()` in
  `register_settings()` for Settings API consistency.
- `wordpress-plugin/includes/Render/AvatarRenderer.php`: extracted `render()`'s
  existing defensive isset->cast->fallback block into a new private
  `apply_defensive_defaults()` helper (render()'s own output/behavior is
  byte-for-byte unchanged — verified by the still-passing
  render-logic-harness.php). Added public `render_floating(): string` which
  returns `''` silently when unconfigured (no admin notice, no visitor
  placeholder — a footer hook has no per-instance context to explain),
  otherwise calls `$this->assets->enqueue()`, resolves
  `get_runtime_config()` through the same `apply_defensive_defaults()` +
  `public_safe()` path `render()` uses, and emits one
  `id="khaveeai-floating"` mount div with `floating: true` added on top of
  `public_safe()`'s existing secret-free whitelist (T-77n-01 — never reads
  the API key or platform key).
- `wordpress-plugin/includes/Plugin.php`: `boot()` now stores the composition
  root's single `AvatarRenderer` instance on a new static
  `self::$floating_renderer` property and registers
  `add_action('wp_footer', array(__CLASS__, 'render_floating_widget'))`.
  The new static `render_floating_widget()` method gates, in order, on
  `is_admin()` (defense-in-depth, T-77n-03), a static once-guard
  (`self::$floating_widget_rendered`, T-77n-04), the persisted
  `floating_widget_enabled` option, and a non-null renderer — then echoes
  `render_floating()`'s already-escaped output.
