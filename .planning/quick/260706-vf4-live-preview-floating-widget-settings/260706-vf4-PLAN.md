<objective>
Add a live visual preview to the WordPress admin Settings page's "Floating Widget"
section so an admin configuring the floating-specific background color / transparency /
avatar offset X-Y / avatar scale can SEE the effect instantly (before saving, no page
reload), instead of guessing at raw hex codes and numbers in blind text/number inputs.

Purpose: The floating-specific config fields added by quick task 260705-p30 are plain
text/number inputs with zero visual feedback (confirmed bad UX by user testing them
blind). This task adds a live preview and better input controls (WP color picker +
range sliders) — reusing the EXISTING preview bundle infrastructure end-to-end.

Output: A second consumer of the already-built `khaveeai-preview` bundle, wired into the
Settings page's Floating Widget section, with instant (unsaved) live updates. No new npm
dependencies, no new preview mechanism, no changes to the Gutenberg block editor's own
preview wiring, no changes to the runtime `FloatingWidget.tsx`.

Key architectural finding (drives the whole plan): the preview mechanism is FULLY
GENERIC and requires ZERO TypeScript/bundle changes:
  - `preview.ts` `init()` calls `observeDocument(document)` (the non-iframe fallback,
    lines 164-170) which scans the TOP admin document for `[data-khaveeai-preview-config]`
    and observes `document.body` for late-added mount points. A mount `<div>` placed
    directly in the Settings form is found by this fallback path (the iframe path is
    Gutenberg-only and simply finds nothing on the Settings screen).
  - `mountPreview.tsx` `PreviewHost` sets up a `MutationObserver` on the mount div's
    `data-khaveeai-preview-config` attribute; any JSON change re-renders `PreviewScene`
    WITHOUT tearing down the WebGL context. Rewriting that attribute from vanilla JS on
    the Settings page is the exact same data-flow the block editor uses.
  - `PreviewScene` reads GENERIC config keys — `avatarUrl`, `bgType` (must be `"color"`),
    `bgColor`, `bgTransparent`, `avatarScale`, `avatarOffsetX`, `avatarOffsetY`. The
    Settings page maps the FLOATING-specific field values into those generic keys.
  - The STUDIO-02 safety guarantee (preview bundle never imports OpenAIRealtimeProvider /
    getUserMedia / ephemeral, enforced by the build.mjs grep assertion) is inherited
    unchanged — this task never touches preview.ts, build.mjs, or the assertion.
</objective>
