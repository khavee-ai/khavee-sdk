# Quick Task 260707-0u6: Settings Page Fixes Batch — Summary

## What changed

Six follow-up fixes to `wordpress-plugin/includes/Admin/SettingsPage.php` based on live-testing feedback after the 260706-vf4/260706-wop/260706-x6b redesign work:

1. **Caption near the Floating Widget live preview** — `render_floating_preview_mount()` now explains that dragging/zooming orbits the camera, while the sliders reposition/resize the avatar. Purely presentational, no behavior change.
2. **Removed "Remove Key"/"Remove Platform Key" checkboxes** — `sanitize_api_key()`/`sanitize_platform_api_key()` dropped the `$remove_requested` param; new decision order is masked-preserve -> blank-removes -> format-reject -> accept-trimmed. Leaving the key field blank and saving now removes it (matches normal web-form expectations). Removed the checkbox fields, their registrations, render methods, and DO-NOT-CHANGE-IDS entries. `settings-page-harness.php` cases rewritten/inverted to cover the new blank-removes behavior while keeping masked-preservation and format-rejection coverage intact.
3. **Live avatar preview in the Avatar section** — new `render_avatar_section_preview_mount()` reuses the same `khaveeai-preview` bundle mount mechanism (distinct `#khaveeai-avatar-preview` id, neutral default framing, passive/non-editable), rendered inside the Avatar card.
4. **Transparent-toggle bug fix attempt #1** — root cause identified as R3F's `<Canvas gl={...}>` prop being initialization-only (same class of issue as the documented `camera`-prop pitfall): `mountPreview.tsx`'s MutationObserver design keeps one persistent WebGL context alive across config edits, so the alpha context freezes at whatever `bgTransparent` was at first mount. Fix applied: `key={config.bgTransparent ? "gl-alpha" : "gl-opaque"}` on `<Canvas>` in both `PreviewScene.tsx` and `mount.tsx`'s `AvatarScene`, scoped to remount only on that specific transition. Bundle rebuilt. **Note: user re-tested live after this fix and reported the bug still occurs — this fix did NOT fully resolve the issue; needs further investigation.**
5. **Purple accent-color** — `render_settings_page_styles()` adds `accent-color: #6929ff` scoped to range/checkbox inputs under `.khaveeai-settings`, replacing default browser blue.
6. **Mock chat transcript in Floating Widget preview** — `render_floating_preview_mount()` now also calls `render_floating_preview_mock_chat()`, reusing the existing `.khaveeai-chat`/`.khaveeai-chat--below`/`.khaveeai-chat__transcript`/`.khaveeai-chat__bubble--{user,assistant}` classes already shipped in the `khaveeai-preview-style` stylesheet — no new CSS/JS, purely static. **Note: user re-tested live and reported the bubbles are not properly contained inside a chat-box visual wrapper — needs a follow-up fix.**
