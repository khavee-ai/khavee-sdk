<objective>
Fix a confirmed bug in `packages/react/src/VRMAvatar.tsx` (shared `@khaveeai/react` SDK package, used by the WordPress plugin's preview mounts AND the main Next.js demo app): when two or more `<VRMAvatar src="SAME_URL" />` instances are mounted simultaneously in different `<Canvas>` scenes on the same page, only ONE displays the model — the other's canvas stays empty with no console errors.

ROOT CAUSE (confirmed via live browser inspection — canvas sizing, camera framing, avatar scale/offset were all ruled out as causes by direct live mutation testing — AND via source-level research against the installed `node_modules`, see `.planning/quick/260708-16h-vrmavatar-shared-scene-instance-fix/260708-16h-RESEARCH.md` for full citations):

`VRMAvatar.tsx` (lines ~199-206) calls `@react-three/drei`'s `useGLTF(src, ...)`, which caches the PARSED GLTF result in a module-global cache keyed `[GLTFLoader, url]` (`@react-three/fiber`'s `useLoader` → `suspend-react`'s cache), shared across every `<Canvas>` on the page — not per-instance, not per-Canvas. Two `<VRMAvatar src="same-url">` instances therefore receive the literal SAME `scene` (`THREE.Group`) and the literal SAME `VRM` object (in `userData.vrm`) back from the cache. A `THREE.Object3D` can only have one parent, so `<primitive object={scene} />` mounting the same object into two different React trees reparents it to whichever instance mounts/reconciles SECOND — leaving the first instance's Canvas scene graph empty. This exactly matches the observed symptom (confirmed live on the WordPress Settings page: the Avatar-section preview and Floating-Widget preview both reference the same configured avatar URL; only one shows it).

Research (already completed, see RESEARCH.md) ruled out two naive fixes:
- `scene.clone()` alone: produces new bone Object3Ds, but the SHARED `VRM` object's humanoid/expressionManager/lookAt/springBoneManager still reference the ORIGINAL bones — expressions/poses would drive the wrong model.
- `SkeletonUtils.clone(scene)` alone (what drei's own `<Clone>` uses internally for skinned meshes): correctly clones the Object3D graph and rebinds skin weights, but does NOT know about or update the sidecar `VRM` object's manager pointers — same problem as above.
- Neither `VRM` nor `VRMCore` (three-vrm 3.4.2) exposes a whole-VRM clone method; `VRMUtils` has no clone helper.

RULED-IN FIX: bypass `useGLTF` entirely. Add a `useVRM(src)` hook that fetches each URL's raw GLB `ArrayBuffer` at most once (module-level `Map<string, Promise<ArrayBuffer>>`, avoiding redundant network fetches), then runs an INDEPENDENT `GLTFLoader.parse()` (with `VRMLoaderPlugin` registered on that loader instance) PER COMPONENT INSTANCE. This produces a genuinely independent `scene`+`VRM` pair for every mounted `VRMAvatar`, with no manual bone re-linking required — the parse itself is what buys independence. The single-instance case (the common path — the main demo app's realtime experience) is behaviorally unchanged: exactly one parse still occurs, no extra network fetch, no visible regression.

Output: `VRMAvatar.tsx` gains a `useVRM(src)` hook and module-level buffer cache; the existing `useGLTF(...)` call is replaced with `useVRM(src)`; downstream logic (mixer, VRMUtils calls, `<primitive object={scene}>`) is adapted to handle the hook's async/nullable loading state (since `useGLTF`'s Suspense-based "always defined by render time" guarantee no longer applies) and to dispose per-instance GPU resources on unmount/src-change.
</objective>

<!--
  Module-level (outside the component, top of VRMAvatar.tsx or a small new file):
    const glbBufferCache = new Map<string, Promise<ArrayBuffer>>();
    function fetchGlbBuffer(url: string): Promise<ArrayBuffer> {
      let cached = glbBufferCache.get(url);
      if (!cached) {
        cached = fetch(url).then((res) => {
          if (!res.ok) throw new Error(`Failed to fetch VRM/GLB: ${url} (${res.status})`);
          return res.arrayBuffer();
        });
        glbBufferCache.set(url, cached);
      }
      return cached;
    }

  New hook (per-instance parse, single effect handles load + cleanup):
    interface VRMParseResult {
      scene: THREE.Group;
      userData: { vrm?: VRM; [key: string]: any };
    }

    function useVRM(src: string): VRMParseResult | null {
      const [result, setResult] = useState<VRMParseResult | null>(null);

      useEffect(() => {
        let cancelled = false;
        let localScene: THREE.Group | null = null;
        setResult(null); // reset to loading state when src changes

        fetchGlbBuffer(src)
          .then((buffer) => {
            const loader = new GLTFLoader();
            // @ts-ignore - VRM loader type compatibility issue (same cast used previously)
            loader.register((parser: any) => new VRMLoaderPlugin(parser));
            return loader.parseAsync(buffer, "");
          })
          .then((gltf: any) => {
            if (cancelled) {
              VRMUtils.deepDispose(gltf.scene);
              return;
            }
            localScene = gltf.scene;
            setResult({ scene: gltf.scene, userData: gltf.userData });
          })
          .catch((error) => {
            if (!cancelled) {
              console.error(`[VRMAvatar] Failed to load ${src}:`, error);
            }
          });

        return () => {
          cancelled = true;
          if (localScene) {
            VRMUtils.deepDispose(localScene);
          }
        };
      }, [src]);

      return result;
    }
-->
