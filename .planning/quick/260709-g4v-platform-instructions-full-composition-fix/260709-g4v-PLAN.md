<objective>
Fix a confirmed cross-repo bug: the WordPress plugin's "Personality / Instructions" field, when synced from the Khavee Platform, only ever reflects `voiceProfile.instructionPrompt` — a small voice-tone fragment — instead of the FULL composed personality+voice instructions the platform (`khavee-app`) actually builds and uses for its own live sessions. This is why the user reported the synced instructions "don't match the one on platform."

ROOT CAUSE (confirmed via direct source reading in both repos, not guesswork):

- `khavee-app/apps/web/src/utils/personalityInstructions.ts`'s `buildPersonalityInstructions(personality, voice, modelDisplayName)` composes a large multi-section system prompt from BOTH the `personality` object (name/description/traits/mood/formality/emoji rule/backgroundStory/exampleConversations) AND `voice.instructionPrompt` (used only as one line: "Apply {voiceInstruction} for tone, personality, and delivery style only — never for language choice."). This is what the platform actually sends to OpenAI as `instructions` for a live session.
- `khavee-app/apps/api/.../project.controller.ts`'s `GET sdk/preview` endpoint (the exact endpoint `wordpress-plugin`'s `PlatformClient` calls) already returns BOTH a `personality` object (displayName/description/traits/backgroundStory/formality/includeEmojis/responseLength/exampleConversations) and a separate `voiceProfile` object (displayName/language/gender/mood/instructionPrompt/openaiVoice) in its JSON response — the data is already there.
- `wordpress-plugin/includes/Platform/PlatformClient.php`'s `map_platform_fields()` (this repo) ONLY reads `voiceProfile.instructionPrompt` and maps it directly to the local `instructions` field, COMPLETELY IGNORING the `personality` object the API already sends. This is the bug.

Output: `PlatformClient.php` gains a `build_personality_instructions( array $data ): string` private static method that ports `buildPersonalityInstructions()`'s section composition into PHP (Identity / Memory / Language & Voice / Thai Speech Rules (conditional) / Response Length / Personality / How to Talk / Hard Rules / If Someone Is Rude / Opening / Knowledge / Examples), consuming `$data['personality']`, `$data['voiceProfile']`, and `$data['model']['displayName']`. `map_platform_fields()`'s `instructions` key is set from this composition's result instead of `voiceProfile.instructionPrompt` alone. The existing harness test asserting a 1:1 `instructionPrompt` → `instructions` passthrough is updated to assert the new composed-string behavior instead (that test's old assumption is now the confirmed bug being fixed, not a behavior to preserve).
</objective>
