# Quick Task 260709-h8x: Block Editor Preview Height Overflow Fix

## Problem

User report: "the global default height is overflowing (only in edit page). it's too much but the chatbox's height is not following the container height."

Root cause (confirmed via Explore agent + source read): when `containerHeight` is 0 ("use global default"), `editor.js`'s preview mount div (`wordpress-plugin/src/editor.js:639-652`) only sets `minHeight: 200`, never an explicit `height`. `.khaveeai-layout { height: 100% }` (styles.css:412-418) and `.khaveeai-chat--beside { height: calc(100% - 32px) }` then have no resolvable ancestor height, so each flex child (avatar canvas vs chat panel) sizes off its own content instead of stretching to match — the block balloons unpredictably in the editor canvas specifically (published front-end doesn't show this because normal page flow tolerates content-driven height; the editor's bounded preview chrome does not).

Settings Page (`SettingsPage.php:2140-2146,2154`) already hit this exact defect and fixed it by hardcoding an explicit `containerHeight`/inline height on its preview mount div. `editor.js` never received the equivalent fix.

## Fix

`wordpress-plugin/src/editor.js`: mount div style now sets an explicit `height` — `live.containerHeight > 0 ? live.containerHeight + 'px' : 400` — instead of only `minHeight: 200`.

Live verification showed this alone wasn't sufficient: `PreviewScene.tsx`'s own container div (nested one level inside the mount div) still left `height` unset, breaking the chain one level deeper (Chromium clamped it to 16777216px). Fixed by defaulting `containerStyle.height` to `"100%"` there too. See SUMMARY.md for full detail.

## Files changed

- `wordpress-plugin/src/editor.js`
- `packages/wp-bundle/src/preview/PreviewScene.tsx`

## Verification

- `npm run build` (wp-scripts build) + `node build.mjs` (wp-bundle) — both compiled clean
- Live-verified in wp-env: canvas computed height 16777216px → 800px; chat panel now stretches to match container
