  <name>Task 1: Add insert() and delete() to KnowledgeClient</name>
  <files>wordpress-plugin/includes/Platform/KnowledgeClient.php</files>
  <action>
Add two public static methods mirroring list_documents()'s exact structure (try/catch(\Throwable), X-API-Key header, TIMEOUT, `data`-shape parsing, generic non-leaking error strings — never embed a raw HTTP body or exception message in the error).

insert( string $key, string $content, array $metadata = array() ): array returning {ok: bool, document: array, error: string}.
- POST to self::BASE_URL via wp_remote_post with:
  'headers' => array( 'X-API-Key' => $key, 'Content-Type' => 'application/json' ),
  'body' => wp_json_encode( array( 'content' => $content, 'metadata' => $metadata ) ),
  'timeout' => self::TIMEOUT.
- Accept 200 OR 201 as success (insert may return 201 Created). Any other status -> 'HTTP '.$status.
- Parse body: require is_array($body) && isset($body['data']) && is_array($body['data']); insert returns {"data": {...single doc...}} so $body['data'] is the doc object — return it as 'document'. Malformed -> 'malformed response'.

delete( string $key, string $id ): array returning {ok: bool, error: string}.
- Call wp_remote_request( self::BASE_URL . '/' . rawurlencode( $id ), array( 'method' => 'DELETE', 'headers' => array( 'X-API-Key' => $key ), 'timeout' => self::TIMEOUT ) ).
- is_wp_error -> 'network error'. Accept 200 OR 204 as success. Other -> 'HTTP '.$status. No body parsing required (a 204 has no body); do not require a `data` key for delete.
- Wrap in try/catch(\Throwable) -> 'unexpected error'.

Both methods get a /** */ JSDoc-style block matching the file's existing doc-comment density (@param/@return with the array shape). Do not add caching (mutations must not be cached). Do not modify search(), list_documents(), or BASE_URL.
  </action>

<task type="auto">
  <name>Task 2: Create authenticated admin REST controller + register it</name>
  <files>wordpress-plugin/includes/Rest/KnowledgeAdminController.php, wordpress-plugin/includes/Plugin.php</files>
  <action>
Create KnowledgeAdminController.php in namespace Khavee\Plugin\Rest, `use Khavee\Plugin\Platform\KnowledgeClient;`, mirroring KnowledgeSearchController's shape (const OPTION_NAME = 'khaveeai_settings'; a private respond(array $data, int $status) helper with Cache-Control: no-store).

register_routes() registers three routes under the 'khaveeai/v1' namespace, path base '/knowledge-admin', ALL with:
  'permission_callback' => function () { return current_user_can( 'manage_options' ); }
(Never '__return_true' — this controller performs privileged mutations. The manage_options check plus the wp_rest cookie-nonce that WP validates for logged-in REST requests is the SET-05-style defense-in-depth gate.)
Routes:
  - GET  '/knowledge-admin'      -> list_documents callback (optional 'limit' param, default 50, clamp to a sane max e.g. 100).
  - POST '/knowledge-admin'      -> create callback (params: 'content' required non-empty string; 'metadata' optional — accept an array or a JSON string and normalize to an array, default array()). Reject empty/blank content with 400 {error:'invalid_content'}. Cap content length defensively (e.g. 20000 chars) mirroring KnowledgeSearchController::MAX_QUERY_LENGTH's rationale.
  - DELETE '/knowledge-admin/(?P<id>[^/]+)' -> delete callback reading $request['id'].

Each callback:
  - Reads $api_key from get_option(self::OPTION_NAME, array())['platform_api_key'] (string, default '').
  - If no key -> respond({error:'no_platform_key'}, 400) (admin context: a real config error the admin should see, unlike the public search route's silent-empty behavior).
  - Calls the matching KnowledgeClient method.
  - On $result['ok'] false -> respond({error:'request_failed'}, 502). Do NOT forward $result['error'] verbatim if it could contain upstream detail — map to a generic code (the client already returns only generic strings, but keep the boundary clean).
  - On success: list -> respond({data: $result['documents']}, 200); create -> respond({data: $result['document']}, 201); delete -> respond({data: array('deleted' => true)}, 200).

Register in Plugin::boot(): add `use Khavee\Plugin\Rest\KnowledgeAdminController;` at top, and directly after the existing KnowledgeSearchController wiring (~line 105):
  $knowledge_admin_controller = new KnowledgeAdminController();
  add_action( 'rest_api_init', array( $knowledge_admin_controller, 'register_routes' ) );
Add a short block comment noting this route IS capability-gated (contrast with the public search route above it). Do not touch SessionController/AvatarRenderer/other wiring.
