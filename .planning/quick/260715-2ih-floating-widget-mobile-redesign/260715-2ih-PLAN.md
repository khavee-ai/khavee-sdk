<objective>
Redesign the WordPress plugin's site-wide FLOATING chat widget (`config.floating === true` path) to match the Khavee Platform's shared/preview mobile layout: the avatar area is always visible with a mic button and a chat-toggle button centered near its bottom edge, and the chatbox — closed by default — slides up as a bottom sheet from the bottom of the screen when the chat button is tapped.

This replaces the current "single launcher opens the whole panel (header + avatar + inline chat) as one block" behavior. The widget-level minimize/launcher and header/close button are preserved (they show/hide the entire floating widget); what changes is the INNER layout and the chat interaction model.

Purpose: Give WordPress-embedded floating widgets the same modern mobile bottom-sheet chat UX the platform's own preview page uses.
Output: A restructured `FloatingWidget.tsx` and reworked floating CSS in `styles.css`. `ControlBar.tsx` and `ChatBox.tsx` are reused as-is (their existing props/placement already cover the new design — do NOT modify them).

Scope guard: `packages/wp-bundle` only. Do NOT touch khavee-app, the inline (non-floating) embed layout, or the shared `.khaveeai-controls` / `.khaveeai-chat--*` base rules used by the inline embed.
</objective>

   - Then the reused `<ChatBox placement="below" />`.
5. Swipe-down-to-close: add a `useRef<number>(0)` for touch-start Y. In `onTouchStart` store `e.touches[0].clientY`. In `onTouchEnd`, compute `deltaY = startY - e.changedTouches[0].clientY`; if `deltaY < -50` (downward swipe past 50px threshold) AND the transcript is scrolled to top, call `setIsChatOpen(false)`. Detect "scrolled to top" WITHOUT modifying ChatBox: use a `useRef<HTMLDivElement>` on the sheet wrapper and read `wrapperRef.current?.querySelector(".khaveeai-chat__transcript")` — treat a missing transcript (empty/disconnected states have no transcript) or `scrollTop === 0` as "at top". This mirrors khavee-app PreviewControls.tsx swipe gesture (reference only — translate the behavior, do not copy Tailwind/React code).

Keep the file's existing header doc-comment style; update it to describe the new always-visible-avatar + bottom-sheet model (note that the launcher/header now govern the whole-widget visibility, and the chat sheet is a separate, default-closed toggle). No fenced code in comments beyond what already exists.
