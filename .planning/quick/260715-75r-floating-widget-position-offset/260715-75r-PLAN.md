<objective>
Site owners embedding the Khavee floating chat widget on a page that already has another floating widget (Intercom/Crisp/Drift, etc.) in the bottom-right corner currently get an overlap — the widget's position (`bottom: 24px; right: 24px`) is hardcoded. Add two configurable options: which corner to anchor to (bottom-right default / bottom-left), and a pixel Y-offset to lift the widget clear of another widget's own footprint. Follow-up to the floating widget mobile redesign (commit a6a161a, this branch).

Scope guard: page-placement CSS only. Do NOT touch the avatar-scene visual config (bg/scale/camera), the bottom-sheet chat redesign, or the inline (non-floating) embed layout.
</objective>

<implementation_notes>
Data flow: WP admin `<select>`/`<input type=range>` (SettingsPage.php) -> sanitize_settings() whitelist/clamp -> wp_options -> WpOptionsConfigSource::get_runtime_config() -> AvatarRenderer::render_floating()'s apply_defensive_defaults() + public config keys (`floatingPosition`, `floatingOffsetY`) -> data-khaveeai-config JSON -> KhaveeAvatarConfig (config.ts) -> FloatingWidget.tsx reads config, sets `data-position` attribute + `--khaveeai-floating-offset-y` inline CSS custom property on the widget root -> styles.css consumes both via `[data-position="bottom-left"]` selector and `calc(24px + var(--khaveeai-floating-offset-y))`.

floating_position is a closed 2-value whitelist (not free-form sanitize_text_field) since styles.css only has CSS for exactly these two values. floating_offset_y is clamped server-side to [0, 400].

Not wired into the SettingsPage avatar-scene live preview (`rebuild()`/mountPreview.tsx) — that preview renders the avatar/camera/background only; page position is fixed-position CSS on the real page, unrelated to the WebGL preview mount's own config.
</implementation_notes>
