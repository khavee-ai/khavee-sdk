# Quick Task 260715-75r: Configurable Floating Widget Position + Offset Summary

Added two WP admin settings so a site owner whose page already has another
floating chat widget (Intercom, Crisp, Drift, etc.) in the bottom-right
corner can move Khavee's widget out of the way: which corner it anchors to
(bottom-right default / bottom-left), and a pixel Y-offset to lift it clear
of another widget's own footprint. Follow-up to the floating widget mobile
redesign (commit a6a161a, this branch).

## What changed

### `packages/wp-bundle/src/config.ts`
- Added `floatingPosition?: "bottom-right" | "bottom-left"` and
  `floatingOffsetY?: number` to `KhaveeAvatarConfig`.

### `packages/wp-bundle/src/floating/FloatingWidget.tsx`
- Widget root now sets `data-position={config.floatingPosition ?? "bottom-right"}`
  and, only when `floatingOffsetY` is non-zero, an inline
  `--khaveeai-floating-offset-y` CSS custom property.

### `packages/wp-bundle/styles.css`
- Base `.khaveeai-floating-widget` rule's `bottom` is now
  `calc(24px + var(--khaveeai-floating-offset-y))` (defaults to `--khaveeai-floating-offset-y: 0px`,
  so `bottom: 24px` for every existing embed — no-op unless the new field is set).
- New `[data-position="bottom-left"]` variant: flips `right`→`left`,
  `align-items: flex-end`→`flex-start`, and the panel's
  `transform-origin` to `bottom left`.
- The `@media (max-width: 480px)` rule was previously unconditional
  (`right: 16px`) — split into a position-aware pair
  (`:not([data-position="bottom-left"]) { right: 16px }` /
  `[data-position="bottom-left"] { left: 16px }`) so mobile still respects
  the chosen corner.

### `wordpress-plugin/includes/Admin/SettingsPage.php`
- New `<select>` field (`render_floating_position_field`) — closed
  2-option whitelist, not free-form text, since `styles.css` only has CSS
  for exactly `bottom-right`/`bottom-left`.
- New `<input type=range>` field (`render_floating_offset_y_field`),
  0–400px step 4, with its own live `<output>` readout wired via a small
  standalone JS listener (NOT folded into the existing `rebuild()` —
  that function feeds the avatar-scene WebGL live preview and these two
  fields are page-placement CSS, unrelated to it).
- `sanitize_settings()`: `floating_position` whitelisted to
  `['bottom-right', 'bottom-left']` (falls back to `bottom-right` on
  anything else); `floating_offset_y` clamped to `[0, 400]`.
- Registered both fields (`add_settings_field` + table row) alongside the
  existing floating-widget-only fields.

### `wordpress-plugin/includes/ConfigSource/WpOptionsConfigSource.php`
- `get_runtime_config()` now reads `floating_position` (default
  `bottom-right` via new `DEFAULT_FLOATING_POSITION` const) and
  `floating_offset_y` (default `0`) from the settings option.

### `wordpress-plugin/includes/Render/AvatarRenderer.php`
- `render_floating()` maps the merged config into `floatingPosition` /
  `floatingOffsetY` on the JSON config object (same pattern as the
  existing `floatingBgColor`/`floatingCameraRotationY` keys — added AFTER
  `public_safe()` so they never leak into the inline-embed's `render()`
  output).
- `apply_defensive_defaults()` re-applies both with the same isset→cast→
  fallback shape as the other floating-only fields.
