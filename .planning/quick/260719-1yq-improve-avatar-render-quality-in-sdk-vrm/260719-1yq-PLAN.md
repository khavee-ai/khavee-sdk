<objective>
Make the SDK's avatar components (`VRMAvatar`, `GLBAvatar`) render with sane, production-quality defaults instead of the current flat, shadow-less, low-anisotropy output — while staying fully backward-compatible with every existing demo page.

Four behaviors, all forced-on-by-default but individually overridable via new optional props:
1. Force `castShadow`/`receiveShadow` on every avatar mesh at load time (today NO shadow flags are set anywhere, so each demo page's `<Canvas shadows>` is a dead no-op).
2. Set texture anisotropy on material maps at load time (sharper grazing-angle rendering).
3. Imperatively force renderer defaults on mount via `useThree()` — ACESFilmicToneMapping + sRGB output color space. This mutates the Canvas-global `gl` instance, not just the avatar — documented at the mutation site as a known/accepted tradeoff.
4. Add a default-on `autoLighting` prop that mounts a basic ambient + directional rig scoped to the avatar group, skippable via `autoLighting={false}` for pages that already hand-roll lights.

Purpose: Devs get good-looking avatars with zero config; power users retain per-prop opt-out.
Output: One shared helper module plus additive prop wiring in both avatar components.
</objective>
